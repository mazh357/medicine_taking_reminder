# ADR-010｜模型工件与推理运行时

## 背景

核心离线运行要求模型、阈值和预处理不依赖网络；历史观察还必须可追溯到原模型版本。

## 决策

创建专用 Expo 原生 `VisionInferenceModule`，直接使用 Google LiteRT/TFLite Android runtime。媒体解密、预处理和推理全部在原生侧进行，只向 JavaScript 返回计数、状态、原因码、manifest 版本和耗时；不得返回照片 Base64/字节、可逆像素缓冲或明文路径。`.tflite`、预处理、阈值、输入输出 schema、版本和 SHA-256 组成随包 manifest；启动时校验。CPU 是首个基线，GPU/NNAPI 默认关闭。历史结果保留 manifest 版本，不自动重算。模型可由构建/本地故障开关整体关闭，且不影响人工主链。

## 备选方案

- Google Play services LiteRT：Google 推荐的 Android 路径之一，但对无 Play 服务设备与 React Native bridge 需额外适配。
- React Native 社区 TFLite bridge：集成较快，但未证明敏感照片的解密像素无需进入 JavaScript。
- 服务器推理：违反离线 P0。

## 代价

需要维护 Kotlin/C++ 原生模块和窄接口；模型随包使安装包增大，升级需发布新安装包。

## 风险

LiteRT/React Native 新架构适配、原生 bridge 越权、GPU delegate 输出差异、模型资产被替换或内存不足。

## 验证

执行 [S00](../architecture/Phase0技术Spike方案_v0.1.md#s00development-build原生模块和构建可复现性) 与 [S06](../architecture/Phase0技术Spike方案_v0.1.md#s06随包-tflitelitert-推理与关闭开关)。未达 P95≤3 s 或稳定性门槛时关闭视觉，而不是更换成联网方案。
