# ADR-001｜跨平台技术路线

## 背景

离线 MVP 需要相机、通知、加密数据库、原生媒体加密、截屏控制和端侧推理，同时由初学者团队维护。当前只验收 Android，但业务规则需为后续 iOS 复用。

## 决策

使用 Expo + React Native + TypeScript 严格模式，单 App、单仓库、单患者数据域，Android 先行；领域和应用层保持纯 TypeScript，平台能力经 ports 接入。iOS 不进入 P0 验收。最低 Android API 由 S00 的 D-L 真机结果冻结。

## 备选方案

- 另一套跨平台语言与框架：生态成熟，但与已冻结的 TypeScript 学习路线不一致。
- Android 原生 Kotlin：平台控制更直接，但会形成第二套 iOS 业务实现。
- Java：适合 Android 原生，不符合跨端单代码库目标。

## 代价

原生边界仍需 Kotlin/Expo Module；CNG/prebuild 和第三方原生库升级增加维护成本。Android 先行不代表所有代码自动可在 iOS 运行。

## 风险

原生依赖最低 API 或新架构兼容性可能迫使调整支持范围；跨端抽象可能掩盖 Android 特有限制。

## 验证

执行 [S00](../architecture/Phase0技术Spike方案_v0.1.md#s00development-build原生模块和构建可复现性)：四类设备构建/安装、原生模块自检、纯领域层无 Expo 依赖。未完成 S00 前不得称为工程签署完成。
