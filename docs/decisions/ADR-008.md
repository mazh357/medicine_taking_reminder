# ADR-008｜领域状态与数量语义

## 背景

照片、模型、任务生命周期和实际服用是不同事实。多药任务还可能只服部分药；实物检测整数不能表达 0.5 片等剂量。

## 决策

分别持久化 `DoseLifecycle`、`ItemConsumptionAssertion`、`PhotoEvidenceState`、`AppearanceAssessment`。每个药项独立保存 `planned_dose_quantity` 与用户给出的 `confirmed_consumption_quantity`；模型只写整数/空的 `detected_object_count`。只有逐药人工确认实际量能追加库存流水；确认、撤销和反向流水同一事务且具幂等键。

## 备选方案

- 单一任务状态：无法表达已准备但未服、多药部分确认和照片删除。
- 模型计数自动扣库存：把画面物体错误当成吞服剂量。
- 覆盖当前余额：无法审计和可靠撤销。

## 代价

状态组合、查询和 UI 派生更复杂；需要十进制定点数量和值对象。

## 风险

任务级派生与药项 pending 处理不一致可能造成提前完成；浮点计算会积累库存误差。

## 验证

执行 [S08](../architecture/Phase0技术Spike方案_v0.1.md#s08集成故障降级与-gate-b-演练)，并由数据契约的属性测试覆盖多药、部分服用、漏服补录、撤销和重复命令。

## 依据（访问日期：2026-08-23）

- 本 ADR 为产品安全语义决策，依据离线 MVP v0.1；不依赖外部医疗判断。
