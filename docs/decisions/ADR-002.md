# ADR-002｜构建与原生能力载体

## 背景

SQLCipher、自定义 AES-GCM 模块和 TFLite 等能力包含构建期配置或原生代码，Expo Go 的固定原生运行时不能代表目标安装包。

## 决策

开发和平台 Spike 使用 Expo Development Build；原生依赖或配置变化后必须重建。性能、零网络、备份和安全验收使用内嵌 JS bundle、关闭开发菜单的 release-like 内部包。Expo Go 不作为开发准入、测试证据或发布载体。

## 备选方案

- Expo Go：启动快，但无法容纳任意原生库/配置。
- Bare React Native：控制充分，但对当前团队增加原生工程维护。
- 仅 EAS 云构建：方便分发，但本地原生调试和受控复现不足。

## 代价

需要 Android Studio/本机构建或受控 EAS 配置；原生依赖变化的迭代速度慢于 Expo Go。

## 风险

Development Build 会连接开发服务器，若误用于零网络测试会产生假失败；开发菜单也不应出现在研究包。

## 验证

执行 [S00](../architecture/Phase0技术Spike方案_v0.1.md#s00development-build原生模块和构建可复现性)，分别保存 development 与 release-like APK 的依赖、配置和 SHA-256。
