# ADR-004｜结构化数据加密与密钥

## 背景

处方、药名、用药事实和研究事件属于敏感本机数据。SQLite 文件、WAL 和 SHM 必须避免明文；密钥不能与数据库同目录保存。

## 决策

`expo-sqlite` 构建期设置 `useSQLCipher: true`；首次启动生成 256-bit 随机数据库密钥，只保存在 `expo-secure-store`，打开库后立即设置 `PRAGMA key`，再执行 schema 访问。密钥不得写日志、诊断包或备份。密钥缺失/失效时进入恢复说明，不创建新明文库、不静默清除。

## 备选方案

- 普通 SQLite + 字段级加密：容易遗漏索引、元数据和新字段。
- 自写原生 SQLCipher bridge：控制更高但重复 Expo 已支持能力。
- 把业务数据存 SecureStore：容量、查询和事务均不适合，官方也不建议将其视为关键数据唯一事实源。

## 代价

SQLCipher 增加包体和打开成本；数据库密钥需要短时进入 JS/native 调用边界；卸载或生物识别配置变化可能使数据不可恢复。

## 风险

`PRAGMA key` 字符串若被日志/错误捕获会泄密；SecureStore 的认证语义在平台和生物识别变化时不同；卸载后 Android Keystore 条目丢失。
