# ADR-005｜媒体加密与敏感显示

## 背景

`expo-camera` 的文件式拍照先保存到应用缓存。照片和缩略图可能暴露用药和疾病线索，不能长期以明文缓存、进入相册或系统备份。

## 决策

通过本地 Expo 原生模块流式执行 AES-256-GCM 单文件加密；每文件唯一 96-bit nonce，认证 tag 与版本化文件头随密文保存，文件名为随机 ID。媒体主密钥与数据库密钥分离，由原生模块在 Android Keystore 中生成并保持不可导出；SecureStore 只保存密钥别名和版本。媒体密钥原文不得进入 JavaScript 内存。密文原子落盘确认后立即删除相机缓存明文；缩略图采用同等加密。敏感路由默认使用 `expo-screen-capture`/`FLAG_SECURE`。

## 备选方案

- 仅依赖应用沙箱：不能防止备份、调试提取或设备失陷后的离线读取。
- Base64 送入纯 JS 加密：内存膨胀、密钥/明文驻留面更大。
- 全部照片存数据库 BLOB：数据库膨胀并加重迁移、WAL 和内存压力。

## 代价

需维护 Kotlin/Expo Module、格式迁移、原子文件协议和密钥生命周期；`FLAG_SECURE` 会限制用户截图分享。

## 风险

GCM nonce 重用会破坏安全；崩溃可能遗留明文/临时密文；Keystore 密钥失效会使历史媒体不可恢复。安全评审和 Phase 0 必须验证媒体密钥不可导出、原生接口不返回密钥原文，并演练密钥失效的只读恢复说明。
