# ADR-014｜纠错、审计与删除

## 背景

直接覆盖服药记录会破坏库存可追溯性；但照片内容又必须允许用户永久删除。两者需要不同的数据生命周期。

## 决策

处方、逐药确认和库存使用版本/追加事件；撤销引用原事实，反向库存流水与撤销在同一事务中提交。漏服后补录保留原漏服事件并新增修订关系。照片删除物理移除密文、nonce、tag、缩略图和临时文件，同时保留不含可恢复内容的墓碑（ID、原关联、删除时间、原因类别）。全部清除销毁数据库、媒体、密钥、研究事件和诊断日志。

## 备选方案

- 直接 UPDATE/DELETE 全部事实：实现简单但无法审计库存来源。
- 永久保留照片：审计完整但违背用户删除权和最小化。
- 软删照片密文：仍可恢复，不符合“永久删除照片内容”的产品语义。

## 代价

查询需计算有效事件；存储会增长；墓碑 schema 和级联关系更复杂。

## 风险

文件系统磨损均衡意味着无法保证对闪存物理扇区的法证级覆写；因此只能承诺删除应用可访问副本并销毁密钥，不得宣称不可被任何手段恢复。

## 验证

执行 S03 的文件删除扫描和 [S08](../architecture/Phase0技术Spike方案_v0.1.md#s08集成故障降级与-gate-b-演练) 的撤销/反向流水；数据契约测试证明幂等和历史可重放。
