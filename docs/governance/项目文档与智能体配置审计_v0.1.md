# 长期用药管理 APP｜项目文档与智能体配置审计

## 0. 审计结论

项目已经完成产品范围和总体技术路线的关键决策，可以进入 Expo/React Native Android 技术 Spike、低保真交互和研究材料准备，但还不能直接招募真实患者。

当前基线已经冻结：

- 离线 MVP 优先于总 PRD、技术架构和本审计。
- Android 先行，使用 Expo + React Native + TypeScript 和 Development Build。
- 照片是记忆凭证；已准备与已服用分开；逐药人工确认才改变库存。
- 端侧视觉只做实物计数、疑似外观变化和拒绝判断。
- 账号、联网、大模型、照护者、奖励、语音、自动快门和用药指导不进入 MVP。
- 内部研究数据本机计算，只有用户主动授权导出后才能离开设备。

阻止真实患者研究的主要缺口是：伦理/研究审批、知情同意、医学安全文案、隐私影响评估、威胁模型、模型评测协议、设备兼容证据及可执行测试追踪仍未完成。

## 2. 已关闭的关键决策

| 决策 | 冻结结果 |
| --- | --- |
| 技术路线 | Expo + React Native + TypeScript，Android 先行，iOS 后续 |
| 构建方式 | Expo Development Build；不以 Expo Go 验收 |
| 拍摄模式 | 手动快门；默认整组一张，可配置逐药拍摄 |
| 拍照兜底 | 允许说明原因后无照片人工确认 |
| 完成语义 | 已准备与已服用两步；逐药确认 |
| 多药 | 每个药项独立实际数量和库存流水 |
| 视觉展示 | 只显示疑似变化或无法判断；内部无异常信号不形成肯定文案 |
| 特殊形态 | 半片、破损片、透明胶囊和同一种药的新旧外观并用只人工确认；整组多药同框不因此回退 |
| 基准版本 | 每种药一个当前外观基准；混用时关闭外观判断 |
| 数量语义 | 实物计数、计划剂量和实际服用量分开 |
| 时间 | 用户为每个方案设置正常窗口结束和最晚记录时间 |
| 计划类型 | 固定日/周计划；不含按需和复杂交替剂量 |
| 处方/复诊 | 用户按已有医嘱手工录入并留原图；无 OCR |
| 医疗内容 | 异常记录＋通用安全分流；无用药禁忌和具体处置建议 |
| 照护/奖励/语音 | 当前 MVP 不包含 |
| 隐私 | 锁屏隐藏；应用锁可选并引导；敏感页默认阻止截屏，可全局放开 |
| 照片 | 本地加密、默认长期、可配置或永久删除，删除留墓碑 |
| 研究数据 | 本机计算，用户授权导出脱敏研究包 |
| 备份 | P1；公开测试前硬门禁 |
| 当前发布性质 | 面向成年患者的内部研究原型，不等同于公开产品 |

## 4. 建议角色与助手配置

智能体可以加速起草和检查，但不能替代真实负责人、专业签署、伦理审批或真机证据。

| 角色/助手 | 主要职责 | 启用时机 | 禁止越界 |
| --- | --- | --- | --- |
| 产品范围负责人 | 维护 MVP、变更记录和需求追踪 | 立即 | 不得把长期愿景直接加入 P0 |
| UX/可用性负责人 | 两步确认、低负担拍照、异常和隐私交互 | UI 编码前 | 不得创造医疗建议或肯定性模型文案 |
| React Native/Expo 跨平台负责人 | 工程底座、原生模块边界、依赖和构建 | Phase 0 | 不得在 UI/store 中复制健康事实；不得暗加联网依赖 |
| Android 平台专项 | 通知、Keystore、截屏、备份排除、厂商限制 | Phase 0 | 不得承诺系统无法保证的提醒送达 |
| 数据与领域契约负责人 | schema、迁移、状态、数量和库存流水 | 正式业务代码前 | 不得混合实物计数与处方剂量 |
| QA/可靠性负责人 | 追踪矩阵、故障注入、真机和长期提醒 | 立即 | 不得只测主路径或用自动化替代真机 |
| 安全与隐私负责人 | 威胁模型、PIA、密钥、媒体、导出和依赖审计 | Phase 0 前 | 不得承诺无法证明的安全删除或恢复 |
| 端侧视觉负责人 | 数据、模型、异常阈值、拒绝判断和模型卡 | 模型 Spike 前 | 不得做开放式识药或自动确认服用 |
| 医学安全负责人 | 异常分流、研究风险、严重不适文案 | 研究材料前 | 不得让未经审核的生成内容上线 |
| 药学安全负责人 | 药物边界和禁用建议审查 | 研究材料前 | 当前版本不得加入个体化处置规则 |
| 研究与伦理负责人 | 方案、同意、招募、退出、事件和销毁 | 真实患者前 | 不得用产品同意代替研究同意 |

### 4.1 最小团队

写正式业务代码前至少明确以下人类责任：产品、React Native/Expo、数据/领域、QA、安全隐私。真实患者研究前再必须加入医学、药学、研究/伦理和端侧视觉责任人。

### 4.2 不建议增加的泛化助手

- 不再增加缺少具体产物和完成标准的“总监型”助手。
- 不把 Android 与 iOS 各自复制为两套业务规则负责人。
- 不设置在线后端、大模型或运营助手，因为当前版本没有相应系统边界。
- 不让同一助手同时起草、审核并签署高风险文档。

## 5. 准入顺序

### Gate A：允许技术 Spike

- 四份基线文档完成本轮一致性检查。
- Phase 0 目标设备、测量方式和失败门槛明确。
- Spike 只验证平台风险，不写正式患者业务。

### Gate B：允许正式业务编码

- 需求追踪、数据字典、交互状态、ADR 和测试策略完成。
- 状态、逐药数量、库存事务和模型契约可机器校验。
- 目标 Android 最小原型验证 SQLCipher、相机、通知、AES-GCM、截屏和 TFLite。

### Gate C：允许真实患者内部研究

- 全部 P0 验收通过，模型关闭时人工主链仍成立。
- 伦理/研究审批、知情同意、招募/退出和数据销毁完成。
- 医学/药学安全文案、PIA、威胁模型和设备矩阵签署。
- 脱敏研究包通过字段白名单和隐私复核。

### Gate D：允许公开测试

- P1 加密备份与恢复演练通过。
- 首发地区、产品宣称、商店披露和支持责任冻结。
- 发布、迁移、回滚和旧版本恢复已演练。

## 6. 风险登记

| 风险 | 影响 | 当前控制 | 仍需证据 |
| --- | --- | --- | --- |
| 每次拍照导致弃用 | 核心假设失败 | 整组一张、手动快门、允许跳过 | 纵向可用性研究 |
| 异常漏报或大量误报 | 错误安全感或告警疲劳 | 不展示通过结论、强制拒绝判断、人工确认 | 模型卡和真实手机分层评测 |
| 多药部分服用记录错误 | 库存和历史失真 | 逐药实际数量和追加流水 | 领域/端到端测试 |
| 半片等特殊形态误处理 | 视觉和剂量混淆 | 实物数与剂量分离、固定人工回退 | 黄金样例和交互测试 |
| 通知延迟或缺失 | 用户错过记录 | 尽力提醒、自检、前台重建 | 长期真机和厂商矩阵 |
| 本机敏感数据泄露 | 隐私伤害 | SQLCipher、媒体加密、锁屏隐藏、截屏控制 | 威胁模型、静态/动态验证 |
| 应用卸载或密钥丢失 | 数据不可恢复 | 当前明确告知；公开前做 P1 备份 | 恢复演练和用户理解测试 |
| 研究导出可重新识别 | 研究隐私风险 | 本机聚合、字段白名单、主动授权 | 隐私复核和攻击测试 |
| 无远程遥测排错困难 | 故障发现慢 | 本地健康页、限额诊断包、真机长测 | 支持 SOP 和故障演练 |
| 内部原型被误当正式产品 | 合规和安全边界扩大 | 研究标识、同意、禁止公开分发 | 分发控制和研究培训 |

## 8. 本轮文档验收

- 当前技术路线只描述 Expo + React Native + TypeScript。
- 不存在面向用户的药物、剂量或安全肯定结论。
- 总 PRD 的联网、大模型、照护和奖励能力明确标为 Future。
- 离线 MVP 不含 OCR、用药禁忌、奖励、语音、自动快门或专项无障碍验收。
- 状态、数量、逐药确认、照片墓碑、库存修订和提醒阈值在产品与架构中含义相同。
- 需求 ID 唯一，Markdown 代码围栏配对，README 链接有效。
- 文档均有状态、日期、优先级、负责人和修订记录或明确待补项。

## 文档结论

项目当前最需要的不是继续扩展产品功能，而是把已冻结的离线闭环转化为契约、交互、真机证据和专业门禁。智能体可负责有边界的起草与核验，但真实患者研究必须由人类产品、技术、QA、安全隐私、医学、药学和研究负责人共同签署。
