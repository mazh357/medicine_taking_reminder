# 个人本地测试版功能完善与交互修改说明

## 0. 文档定位

本文冻结“长期用药助手｜个人本地测试版”的目标修改。主体代码已按本文实施，并已扩展到 schema v4：包括库存预测与补药提醒、复诊/取药/检查事项、历史筛选、跨天对账、中性通知，以及用户确认物理清除全部数据后自动重建空白安全运行时。当前自动化门禁为 29 个测试文件、138 项测试通过。

2026-08-25/26 的旧版本构建与模拟器证据见[个人本地测试版高风险验收记录](../quality/个人本地测试版高风险验收记录_2026-08-25.md)，但该证据不覆盖当前代码。当前事实见[2026-08-27 功能验收记录](../quality/个人本地测试版功能验收记录_2026-08-27.md)：`npm run check` 为 29 个测试文件、138 项通过；修复后 x86_64 Release 已完成静态属性、API 36 干净离线冷启动、修复前包覆盖、异常明文库保护、二次启动和前后台切换。真实 v3 包与 ARM 真机仍待验证。

真机磁盘密文、密钥异常、备份恢复、照片物理删除和锁屏通知尚待取证与人类签署，因此 `realPatientDataAllowed=false`；在本文第 4、11 节门禁全部完成前，不得在当前 APK 中录入真实药名、处方、药物照片或其他个人健康数据。本文不改变 Gate B、Phase 0、公开测试或真实患者研究的门禁结论。

本次目标调整包括：产品名称与文案简化、通用计数单位、双列时间选择、连续任务和提醒闭环、计划修改、库存预测与补药提醒、事项管理、历史筛选、设置扩展、照片管理、错误恢复及个人数据本地加密。

## 2. 产品名称、启动和提示

### 2.1 名称与入口

- Android 可见名称、通知标题和页面产品名统一为“长期用药助手”。
- Android 包名 `com.helpusurvive.medicationdemo` 与 Scheme `medicationdemo` 暂不修改，避免产生安装身份和深链迁移。
- 删除首次声明页、勾选项、接受动作和以 `demo_profile` 为准入条件的路由。
- 冷启动完成本地运行时初始化后直接进入“今天”。初始化或密钥异常仍进入相应恢复页，不得绕过错误进入业务页面。
- 删除用户可见的“载入虚构演示方案”入口。自动化测试可继续使用不出现在生产界面的内部测试数据。

### 2.2 文案简化

删除全局 Demo 横幅，以及用户界面中的“虚构”“演示药”“禁止录入真实信息”“照片不代表服用”“计数不是剂量”等重复说明。底层仍必须保持三个数量字段分离，任何视觉结果仍不得写入实际服用量或库存。

只保留以下类型的信息：

- 删除单张照片和清除全部数据等不可逆操作的确认；
- 权限请求、字段校验、存储不足、密钥异常和保存失败等操作性信息；
- 操作进度、成功结果和可恢复失败状态。

页面用语统一采用普通产品文案，例如“用药计划”“新增药物”“药物名称”“保存”“库存”“今天”和“记录”。不使用“保存演示药项”等按钮文案。

### 2.3 已接受的残余风险

界面不再重复说明照片、计数与实际服用量的边界，可能提高误解风险。该风险不通过放松数据规则解决：代码审查、接口隔离和自动测试必须继续证明 `detectedObjectCount` 不能生成服用确认或库存流水。

## 3. 药名、数量与时间输入

### 3.1 药名

- 药名必填，去除首尾空白后长度为 1—60 个 Unicode 字符。
- 允许中文、英文、数字、空格及常见药名/规格标点。
- 拒绝换行、制表符、其他控制字符和纯空白值。
- 不判断名称是否为真实药物，不根据名称提供剂量、安全或相互作用建议。

### 3.2 通用计数

- 删除“片/粒”选择、字段、筛选和所有界面后缀。
- 页面显示“计划数量 1”“实际数量 0.5”“库存 20”。
- UI、应用接口和领域契约使用 `QuantityUnit = "count"`。
- 数量继续使用十进制定点规则，允许 0—999999.999；计划数量必须大于 0，库存不得小于 0。
- 照片检测物体数仍为非负整数，不能因通用计数单位而转换成服用量。
- 目标版本不迁移旧 `tablet/capsule` 数据；旧库在安全升级流程中整体清除。

### 3.3 双列提醒时间选择器

- 表单不再接受键盘时间文本。
- 点击时间字段打开双列选择器：左列 `00—23`，右列 `00—59`。
- 当前值打开时居中定位；首次创建默认 `08:00`。
- 两列按固定行高滚动并吸附，值始终补零显示为 `HH:mm`。
- `取消`不写入变化，`确定`提交当前两列值。
- 支持读屏标签“小时”“分钟”，并提供增加/减少可访问性动作。
- 失焦、旋转或页面返回不得提交未点击“确定”的临时值。

## 4. 真实个人数据与加密门禁

### 4.1 一次性升级清理

目标版本首次启动时检测旧 Demo 存储标记。发现旧普通 SQLite 或旧媒体目录后按以下顺序处理：

1. 停止进入业务页面；
2. 取消全部旧本地通知；
3. 删除旧 SQLite 主文件、WAL、SHM、旧照片目录和可识别的临时缓存；
4. 清除旧 Demo 专用偏好和命令记录；
5. 创建新密钥和加密数据库；
6. 记录不含健康数据的升级完成标记；
7. 进入空白“今天”页。

旧 Demo 数据不提供迁移或恢复。升级完成后仅显示一次“旧测试数据已清除”的结果信息，不显示产品声明。

### 4.2 SQLCipher

- Expo SQLite 构建启用 SQLCipher。
- 首次建库生成独立的高熵数据库密钥；密钥只通过 SecureStore/Android Keystore 保护。
- 每次打开数据库必须先应用密钥，再读取 schema 或执行业务查询。
- 日志、错误消息、测试快照和诊断信息不得包含密钥或完整 SQLCipher PRAGMA。
- 数据库、WAL、SHM、SecureStore 和相关暂存文件全部排除 Android 自动备份。

### 4.3 AES-GCM 照片

- 使用 Android 原生能力为每个照片文件生成唯一 96 位 nonce，以 AES-GCM 加密并验证认证标签。
- 持久文件保存版本头、算法标识、nonce、密文和认证标签，不保存明文副本。
- 相机临时明文在加密成功、失败或用户离开流程后均尝试清理。
- 展示和端侧计数只能生成随机命名的短期解密缓存；使用结束、App 退到后台、冷启动和全部清除时删除。
- 解密缓存不得进入系统相册、媒体索引或自动备份。

### 4.4 密钥和解密失败

- 密钥缺失、数据库认证失败或照片解密失败时不得自动重建并覆盖旧数据。
- 数据库级失败提供 `重试`和`清除本机数据`；清除必须再次确认。
- 单张照片失败显示不可用状态，结构化任务、服用事实和库存仍可读取时不得一并删除。
- 清除全部数据必须销毁数据库、照片、解密缓存、本地通知、偏好和密钥。
- 物理清除完成后，应用自动生成新的密钥和空白 schema v4 运行时；不得恢复已删除的健康数据或旧提醒。

### 4.5 离线边界

核心功能不得加入网络、遥测、广告、远程日志、远程配置、运行时更新或大模型依赖。Development Build 为 Metro 使用的网络能力不能作为 release-like APK 的业务联网依据；最终包必须通过飞行模式和网络请求审计。

## 5. 连续任务与本地提醒闭环

- 每次冷启动和回到前台时，按本地日期生成缺失的当日任务，并保证同一计划同一日期最多一个有效任务。
- 对所有任务执行时间对账：到计划时间推进为 `due`，超过最晚记录时间且仍未完成时保留漏服事件并推进为 `missed`。
- “今天”展示全部当日任务，不再只取第一条；按计划时间排序并分别显示进度。
- 数据库保存提醒意图、任务 ID、计划触发时间、系统通知 ID、投影状态和最近对账时间。
- 通知点击携带任务 ID并进入对应任务；已完成或撤销任务进入只读历史。
- 冷启动、前台恢复、计划变化和权限恢复时对账系统通知，取消过期/失效投影并补建缺失提醒。
- 提醒失败不删除任务；设置页显示失败状态并允许重试。
- 锁屏及通知列表默认只显示“用药提醒”“你有一项计划需要处理”等中性内容，不显示药名、剂量、库存、事项标题或备注。
- 冷启动、回到前台和本地日期变化时同时对账用药任务、补药提醒和事项提醒；系统通知只是可重建投影，数据库中的提醒意图才是事实来源。

## 6. 计划修改、库存预测与补药提醒

开放药名、计划数量、提醒时间、暂停、恢复和库存校正。单位不存在编辑入口。

- 当前任务为 `scheduled` 且新提醒时间仍晚于当前时间时，修改今日生效。
- 旧任务保留并标记为计划替换，新计划生成新的今日任务和通知。
- 当前任务已到期、已准备、已确认、漏服或撤销时，修改次日生效。
- 新提醒时间不晚于当前时间时自动改为次日生效，并在保存结果中显示生效日期。
- 暂停时撤销尚未开始的今日任务；已开始任务不受影响，次日起停止生成。
- 恢复时若今日提醒时间尚未来到则生成今日任务，否则次日恢复。
- 库存校正由用户输入目标库存，系统追加差额为 `manual_adjustment` 的流水，不覆盖历史流水。
- 计划数据库事务成功但系统通知更新失败时保留计划变更，并标记提醒投影待重建。

库存预测和补药提醒采用以下已实现规则：

- 每种药物显示当前库存余额，并依据当前启用的每日固定计划计算预计用尽日和下一次库存不足日；
- 计划暂停、没有启用计划、余额异常或当前计划无法可靠计算时，显示明确的不可预测原因，不生成猜测日期；
- 每种药物可选择不提醒，或提前 3、7、14、30 天提醒补药，新建药物默认提前 7 天；
- 补药提醒意图和系统通知投影分开保存，库存、计划或偏好变化后重新计算并对账；
- 预测结果只用于库存安排，不构成改变服药、补服、停药或调整剂量的建议。

## 6.1 复诊、取药和检查事项

- 一级“事项”页面支持新增、修改、完成和取消复诊、取药及检查事项；
- 字段包括类型、标题、日期时间、可选关联药物、备注和提前提醒；
- 提前提醒支持不提前，或提前 1、3、7 天；到期提醒与提前提醒分别建立本地提醒意图；
- 完成和取消均保留追加事件，不直接抹除事项历史；已完成或已取消事项不可继续编辑；
- 事项标题、备注和关联药物不得进入锁屏通知文案；事项功能不提供检查解读、复诊处置或其他医疗建议。

## 7. 设置、外观与自检

设置首页只展示已经实现且可执行的入口：

| 分组 | 功能 |
| --- | --- |
| 用药与计划 | 启用/暂停数量、进入计划列表、计划修改与库存校正 |
| 设备与提醒 | 通知/相机权限、测试提醒、打开系统设置、SQLite/照片目录/加密状态 |
| 外观与文字 | 跟随系统/浅色/深色，标准/大/特大文字 |
| 照片与数据 | 数据概况、照片管理、全部清除 |
| 版本信息 | 应用版本、构建号、离线状态、数据库和媒体格式版本 |

主题和字号契约：

- `ThemeMode = "system" | "light" | "dark"`，默认 `system`；
- `TextSize = "standard" | "large" | "extra_large"`，应用倍率为 `1.0 / 1.15 / 1.30`；
- 保留 Android 系统字体缩放，不以 App 偏好禁用系统无障碍；
- 修改立即生效并持久化到加密数据库。

设备自检显示通知权限、相机权限、本地提醒调度、数据库可读写、媒体目录可读写、密钥和加密格式状态及最近检查时间。自检不得读取、展示或导出药名与照片内容。

设置页提供“1 分钟后测试提醒”，其忙碌状态和错误反馈与设备自检相互独立；版本信息从运行时读取 schema 和媒体格式，不硬编码版本号。

## 8. 照片时间线与逐张删除

- 历史按时间展示全部拍摄和重新拍摄证据，不只展示最后一张。
- 每张有效照片提供短期解密预览、拍摄时间、关联任务和单张删除入口。
- 删除需二次确认；成功后物理删除密文、相关解密缓存和缩略派生物，并将结构化记录改为 `deleted_tombstone`。
- 墓碑保留照片 ID、原任务关联、删除时间和原因类别，不保留路径、nonce、认证标签或可恢复内容。
- 照片删除不删除计数观察、服用事实、库存流水和任务历史。
- 文件或墓碑写入部分失败时不得显示完成；操作可安全重试。

### 8.1 历史事实与筛选

- 历史页只展示已有照片/跳过记录、逐药确认、漏服、修订或撤销等实际事实的任务，纯计划任务不进入历史；
- 日期筛选支持近 7 天、近 30 天和全部；
- 药物筛选支持全部药物或单一药物；
- 结果筛选支持按计划、部分或混合、未服用、漏服和已撤销；
- 筛选只改变展示，不修改任务、逐药事实、照片证据或库存流水。

## 9. 错误恢复和交互可靠性

- 所有写按钮提交期间禁用，避免重复点击；幂等命令继续作为第二道保护。
- 新增药物、修改计划、确认、修订、撤销、拍照、解密和清除均提供行内进度及可读错误。
- 存储不足时不得显示照片已保存；允许重试或返回，不破坏原任务。
- 照片计数崩溃、超时或设备不支持时结束等待并进入人工流程。
- 通知失败、权限拒绝和系统设置返回后均可重新自检。
- 错误信息不包含密钥、绝对私有路径、完整处方或照片内容。

## 10. 目标接口与替换映射

### 10.1 公共类型

```ts
type MedicationInput = {
  name: string;
  plannedDoseQuantity: number;
  initialInventory: number;
  reminderTime: string; // HH:mm
};

type ThemeMode = "system" | "light" | "dark";
type TextSize = "standard" | "large" | "extra_large";
type QuantityUnit = "count";

type PlanChangeResult = {
  effectiveLocalDate: string;
  effective: "today" | "tomorrow";
  replacedOccurrenceId?: string;
  newOccurrenceId?: string;
};

type LocalDataSummary = {
  medicationCount: number;
  occurrenceCount: number;
  activePhotoCount: number;
  deletedPhotoCount: number;
  encryptedPhotoBytes: number;
};

type RefillReminderDays = 0 | 3 | 7 | 14 | 30;
type FollowUpType = "follow_up" | "refill" | "test";
type AdvanceReminderDays = 0 | 1 | 3 | 7;
```

`DemoApi` 已由中性的 `MedicationAppApi` 能力替代，并提供计划修改、暂停/恢复、库存校正、库存预测与补药偏好、事项管理、任务/提醒对账、权限与加密自检、偏好读写、完整照片列表、解密预览、单张删除、数据概况和全部清除。界面不得直接访问 SQLite、SecureStore、Keystore 或文件系统。

新加密数据库当前使用 schema v4：在 schema v3 基础上增加库存预测偏好、事项、事项追加事件、辅助提醒意图及其可重建投影；既有照片 `initial/retake` 契约继续保留。schema v2 可依次升级到 v3、v4；不存在从旧未加密 schema v1 导入业务数据的路径。

## 11. 实施阶段与硬门禁

1. **安全基础：** 清除旧 Demo、SQLCipher、SecureStore/Keystore、AES-GCM、缓存清理和备份排除。
2. **领域迁移：** 中性药名、`count` 单位、目标 schema、接口改名和旧准入删除。
3. **连续主链：** 跨日任务、状态推进、多任务首页、提醒意图、深链和重建。
4. **交互改版：** 双列时间选择、普通文案、计划修改、库存预测、事项、历史筛选、设置、主题和字号。
5. **照片与恢复：** 加密预览、完整时间线、逐张删除、墓碑和错误恢复。
6. **交付验收：** release-like APK、飞行模式、重启、跨日、真机通知、密钥和删除测试。

代码实现和自动化门禁通过不等于真实个人数据准入。`realPatientDataAllowed` 必须保持 `false`，直到 Android 真机安全证据、隐私与医学安全评审及相应人类签署全部完成。

## 12. 验收标准

- 当前未加密数据库和媒体在升级后被清除，不能被目标版本继续读取。
- SQLCipher 无密钥无法读取；照片密文不能作为普通图片打开；错误密钥或篡改认证失败。
- 密钥缺失不会触发自动清空；只有用户确认后才能全部清除。
- 相机临时文件和解密缓存按成功、失败、后台、冷启动和全部清除场景清理。
- 药名无需“演示”前缀，片/粒选择及界面后缀全部消失。
- 所有提醒时间只能由双列选择器生成合法 `HH:mm`。
- 三个数量字段保持独立；照片物体数不能产生确认或库存流水。
- 同日多任务全部可见；跨日生成、到期、漏服和通知深链正确。
- 计划修改、暂停/恢复和库存校正保留历史且通知可重建。
- 库存余额、预计用尽日和下次不足日相互区分；不可预测时显示原因；每药补药提醒只允许无、3、7、14、30 天。
- 复诊、取药和检查事项可新增、修改、完成和取消；提前提醒只允许无、1、3、7 天，事件和提醒意图可追溯。
- 历史只显示已有实际事实的记录，日期、药物和结果筛选不改变底层事实。
- 跨天对账覆盖用药、补药和事项提醒；通知正文不泄露药名、剂量、库存、事项标题或备注。
- 用户确认全部清除后，旧数据库、媒体、缓存、通知、偏好和密钥被物理删除，并重建空白安全运行时。
- 浅色、深色、系统主题和三档文字在重启后保留。
- 全部照片和重新拍摄照片可查看；单张删除保留墓碑和其他历史。
- 飞行模式下完整闭环可用，release-like APK 不依赖 Metro。

## 13. 范围边界

目标版本仍不包含服务器账号、同步、云备份、OCR、开放式识药、大模型、在线问诊、照护者、奖励、语音或医疗建议。它是单一用户、本机离线的个人测试版，不等同于公开发布、真实患者研究或医疗器械结论。

单位和提示精简当前只冻结给个人测试版。正式 PRD、离线 MVP、数据字典和总体技术架构是否继承这些决策，须在个人测试验证后单独评审；本文不直接改写正式基线。
