## 3. 冻结的跨文档决策

### 3.1 任务与药项

- `DoseLifecycle` 是任务级可重建汇总投影，不代表每种药的服用事实。
- 所有药项完成且至少一项实际量大于 0 时，按时间派生 `taken_confirmed` 或 `late_taken`。
- 全部药项明确未服，或最晚记录时间仍存在 pending 时，任务派生为 `missed`。
- 页面、导出和统计必须同时读取逐药 `ItemConsumptionAssertion`。

### 3.2 照片与视觉

- 合法的整组多种药同框不是“混合外观”。
- 强制回退只针对同一种药的新旧厂家、批次或外观版本并用，以及半片、破损片、透明胶囊等冻结条件。
- P0 外观原因只允许 `color | shape | texture | imprint`；没有实体尺度参照，不提供 `size`。
- `no_anomaly_signal` 仅为内部状态，不生成通过、安全或正确性用户结论。

### 3.3 媒体安全与推理

- 媒体主密钥由 Android Keystore 生成并保持不可导出，不进入 JavaScript 内存。
- SecureStore 保存数据库密钥及媒体密钥别名/版本，不保存媒体主密钥原文。
- 采用专用原生 `VisionInferenceModule` 和 Google LiteRT/TFLite Android runtime。
- 解密、预处理、推理和受控显示留在原生侧；JavaScript 不得取得媒体密钥、数据密钥、照片 Base64/字节、可逆像素缓冲或明文路径。
- 若该边界无法通过 Spike 证明，关闭视觉能力，人工主链保持可用。

## 5. 允许与禁止的下一步

### 5.1 附条件允许

- 建立一次性 Expo Development Build Spike 工程。
- 编写无真实健康数据的系统能力探针和自动检查器。
- 将数据字典转为 schema/类型/迁移测试草案，但不得声明已通过真机门禁。
- 制作低保真交互原型和文案评审稿。

### 5.2 仍然禁止

- 招募或导入真实患者、处方、药品照片和研究数据。
- 在未完成 S00—S08 前启动正式患者业务实现或对外分发。
- 启用未经模型评测协议验证的外观提示。
- 放宽原生媒体/推理边界以换取开发便利。
- 引入账号、服务器、大模型、照护者、奖励、语音、自动快门或个体化用药建议。

## 6. 后续门禁

- **Gate C（真实患者内部研究）：** 需要伦理/研究审批、知情同意、医学/药学安全文案、PIA/威胁模型人类签署、模型评测与设备矩阵真机证据。
- **Gate D（公开测试）：** 需要加密备份/恢复、首发地区评估、商店披露、发布/迁移/回滚及公开支持流程。

## 7. 最终判定

本项目已经具备执行 Phase 0 和生成正式工程任务清单所需的决策完备文档，但尚未取得平台、安全和性能的真机证据。因此 Gate B 当前为“附条件通过”：只允许技术 Spike 和非患者原型；正式业务编码需在 B-01—B-10 关闭后由主负责人重新签署为“通过”。
