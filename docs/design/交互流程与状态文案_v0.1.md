# 长期用药管理 APP｜交互流程与状态文案

> 本文把离线 MVP 转换为可制作低保真原型和实现页面的交互契约。若本文与离线 MVP 冲突，以离线 MVP 为准。本文中的安全分流内容均为占位符，未经医学负责人签署不得进入真实患者版本。

## 0. 文档控制

### 0.1 冻结范围

- 对象限能独立确认的成年口服片剂或胶囊长期用药患者。
- 核心闭环为：提醒 → 拍照或说明跳过原因 → 已准备 → 逐药确认 → 逐药扣库存 → 时间线回看。
- 所有页面必须在飞行模式下可进入和完成；系统分享研究包是用户主动离开 App 的动作。
- 相机、端侧分析或系统提醒不可用时，人工记录主链仍必须成立。
- 当前页面不得包含远程服务、生成式咨询、第三方代操作、激励养成、声音交互、自动拍摄或个体化用药指导入口。

### 0.2 文案原则

1. 照片只称“照片记录”或“记忆凭证”，不称“服药证据”。
2. `prepared` 固定显示“已准备”，并紧邻提示“尚未确认已服用”。
3. 用户可见的视觉结果只有“疑似发生变化”和“无法判断”；内部 `no_anomaly_signal` 不生成结果卡片。
4. `detected_object_count` 固定称“画面中检测到的物体数”，不得称“服用量”或“剂量”。
5. 时间阈值固定称“记录时间范围”，不得解释为医学允许的服药窗口。
6. 异常页面只帮助记录和求助分流，不给出补服、加倍、停药、抵消或改量方案。
7. 危险操作说明具体后果，并要求二次确认；不使用羞耻、惩罚或依从性评分文案。

### 0.3 状态显示契约

| 数据维度 | 内部值 | 用户标签 | 页面规则 |
| --- | --- | --- | --- |
| 任务生命周期 | `scheduled` | 未到时间 | 只读显示计划；允许提前查看，不提供整组确认 |
| 任务生命周期 | `due` | 待记录 | 可拍照、说明跳过原因或查看药项 |
| 任务生命周期 | `prepared` | 已准备·待确认 | 明示“照片或跳过原因已保存，尚未确认已服用” |
| 任务生命周期 | `taken_confirmed` | 已完成记录 | 所有药项均非待确认，且在正常记录时间内完成 |
| 任务生命周期 | `late_taken` | 晚于正常时间记录 | 所有药项均非待确认，完成时间晚于正常窗口结束 |
| 任务生命周期 | `missed` | 本次未完成服用记录 | 截止时仍有待确认项，或全部药项明确未服用；保留逐药事实，可补充实际记录，不自动扣库存 |
| 任务生命周期 | `revoked` | 已撤销 | 原确认保留只读，显示修订链和反向库存流水 |
| 药项确认 | `pending` | 待确认 | 不填实际量，不扣库存 |
| 药项确认 | `taken_as_planned` | 按计划量服用 | 实际量默认等于计划量，提交前仍由用户核对 |
| 药项确认 | `partially_taken` | 与计划量不同 | 必须由用户填写实际量，允许为零以外的小数 |
| 药项确认 | `not_taken` | 未服用 | 实际量固定为 0，不扣库存 |
| 照片证据 | `captured` | 已保存照片 | 仅在加密保存成功后显示 |
| 照片证据 | `skipped_with_reason` | 本次无照片 | 必须显示原因类别；其他原因自由文本只留本机 |
| 照片证据 | `deleted_tombstone` | 照片已永久删除 | 不显示或恢复缩略图；显示删除时间 |
| 视觉结果 | `suspected_change` | 疑似发生变化 | 提示核对照片、包装、厂家/批次和已有处方，不阻断逐药确认 |
| 视觉结果 | `unable` | 无法判断 | 说明本次只能人工核对，不阻断逐药确认 |
| 视觉结果 | `no_anomaly_signal` | 无用户标签 | 不显示“通过”卡片，只继续照片与逐药表单 |

### 0.4 数量显示契约

| 字段 | 页面名称 | 输入/显示规则 |
| --- | --- | --- |
| `detected_object_count` | 画面中检测到的物体数 | 只读整数或“未得到结果”；与任何药项实际量不联动 |
| `planned_dose_quantity` | 本次计划量 | 来自当前任务引用的处方版本，只读，可为小数 |
| `confirmed_consumption_quantity` | 本次实际量 | 每个药项分别由用户确认，是库存扣减的唯一依据 |

## 1. 信息架构与全局交互

### 1.1 一级导航

| 入口 | 默认内容 | 空状态主要按钮 |
| --- | --- | --- |
| 今日 | 提醒健康状态、当前及今日任务、逐药完成情况 | `添加第一份用药方案` |
| 用药 | 处方版本、药物、外观基准、计划、库存 | `新增药物` |
| 记录 | 时间线、照片状态、逐药实际量、异常与修订 | `记录异常` |
| 事项 | 复诊、取药、检查项目、本地摘要 | `新增事项` |
| 设置 | 通知、应用锁、截屏、照片保留、研究导出、数据清除 | 无 |

相机不作为固定底部入口；用户从今日任务或通知进入，避免产生无法关联任务的孤立服药照片。处方、包装和基准照片从对应编辑页进入拍摄。

### 1.2 全局保存规则

- 表单离开前若有未保存修改，弹窗标题为“保存本次修改吗？”，按钮为 `继续编辑`、`放弃未保存内容`、`保存`。
- 逐药确认是事实写入，不使用通用自动保存。每个已提交药项显示提交时间；未提交草稿仅保留在当前会话。
- 所有时间显示本地日期、时刻和当前时区；检测到时区或系统时间变化时，首页置顶告警，在用户核对前暂停自动派生未来任务。
- 任何后台处理不阻挡返回：照片保存成功后即可继续，端侧分析使用行内状态“正在进行辅助查看，不影响继续记录”。

### 1.3 提醒健康条

| 状态 | 标题 | 正文 | 操作 |
| --- | --- | --- | --- |
| 正常 | 提醒已开启 | 下次预计提醒：{本地时间} | `发送测试提醒` |
| 权限关闭 | 提醒权限已关闭 | 系统可能不会显示用药提醒，你仍可从“今日”查看任务。 | `打开系统设置` |
| 只能近似提醒 | 提醒时间可能有偏差 | 当前设备限制精确调度，提醒可能提前或延后。 | `查看说明` |
| 需重建 | 正在检查提醒 | 计划、时区或设备状态发生变化，正在重建未来提醒。 | 无 |
| 重建失败 | 部分提醒未能创建 | 请检查系统权限；任务仍会保留在“今日”。 | `重试`、`打开系统设置` |

不得使用“保证准时”“不会漏提醒”等表述。

## 2. 首次设置流程

首次设置使用 8 步进度页。用户可在完成边界确认后退出并下次继续；没有完整药物和计划时首页显示设置未完成，不生成任务。

### 2.1 步骤 1：产品边界确认

标题：`先了解这个工具能做什么`

正文：

> 这个 App 帮你记录已有处方、提醒时间、照片和你本人确认的服用情况。照片只能帮助回忆，不能证明药物已经服下。端侧辅助查看不能确认药名、成分、剂量或是否安全。

必选确认项：

- `我知道照片不代表已经服用。`
- `我知道辅助查看不能代替本人核对或专业判断。`
- `我会按已有处方或医嘱录入，不使用 App 改变用药。`

主按钮：`同意并继续`。未全部勾选时禁用。保存边界内容版本；版本重大变化时重新展示。

### 2.2 步骤 2：本机与隐私

标题：`记录只保存在这台设备`

正文：`当前版本没有账号或在线恢复。卸载 App、设备损坏或系统密钥丢失，可能导致记录无法恢复。`

应用锁卡片：`建议使用设备生物识别或 PIN 保护敏感记录。` 操作为 `启用应用锁`、`暂不启用`。拒绝不阻断设置。

### 2.3 步骤 3：建立处方版本

字段：版本备注、生效日期、可选疗程结束日、处方原图。处方原图拍摄页固定提示：`照片仅供你回看，内容不会自动填入表单。`

药项由用户逐个添加：药名、剂型（片剂/胶囊）、规格、计划单位、备注。保存前摘要逐字段回显，按钮为 `确认这些内容由我录入`。

### 2.4 步骤 4：药物外观与基准

每种药依次拍摄包装、药片正面、药片背面，并填写厂家/批次备注。页面仅允许一个“当前使用中”基准。

特殊形态选择：`半片`、`破损片`、`透明胶囊`、`新旧外观同时在用`。选择后显示：`这种情况不进行外观辅助判断，照片仍会保存，之后由你人工核对。`

同一种药的新旧外观同时在用时不可激活新基准，药物卡片显示 `外观判断已关闭·同药新旧外观并用`。待用户确认只剩一种外观后，创建并激活新版本。不同计划药物共同入镜是合法整组场景，不触发该提示。

### 2.5 步骤 5：初始库存

字段：当前持有量、单位。辅助说明：`请按你实际持有的数量填写。库存是估计值，可以之后修订。`

若单位为片，可输入十进制定点小数；错误文案：`请输入大于或等于 0 的数量，最多按系统支持的小数位填写。` 不从照片或包装自动推算。

### 2.6 步骤 6：固定计划与拍摄方式

计划类型仅显示：`每天固定时间`、`每周指定日期`。每日可添加多个时间。每个时间槽必须设置：

- 提醒时间；
- 正常记录截止时间；
- 最晚记录时间。

字段说明：`这些时间只用于记录分类和提醒，不代表医学上的服药时间范围。请按你的既有安排设置。`

校验：正常记录截止时间晚于提醒时间；最晚记录时间晚于正常记录截止时间且早于同方案下一任务。错误时指出冲突的两个时间，不允许保存。

拍摄方式单选：`整组拍一张（默认）`、`每种药分别拍摄`。说明：`无论选择哪种方式，之后都要逐种确认实际服用量。`

### 2.7 步骤 7：复诊与事项

用户可添加复诊、取药和检查项目。字段为标题、日期时间、关联处方/药物、备注。固定提示：`只记录已有医嘱；App 不会推荐检查项目或周期。` 允许跳过。

### 2.8 步骤 8：通知自检与完成

先解释中性锁屏文案示例“该记录用药了”，再请求系统通知权限。授权后创建测试提醒；拒绝后展示提醒健康条和系统设置入口，但允许完成设置。

完成页逐项汇总药物、计划、拍摄方式、库存和事项；按钮 `完成设置`。不得展示综合“方案正确”结论。

## 3. 今日任务与拍照

### 3.1 今日任务卡

任务卡显示计划时间、任务生命周期标签和药项完成数（例如“2/3 项已确认”）。锁屏通知仅显示中性文案，点击后通过任务 ID 打开相应任务。

| 情况 | 主按钮 | 次按钮 |
| --- | --- | --- |
| `due` 且无照片状态 | `开始记录` | `查看药项` |
| `prepared` 且有待确认药项 | `继续逐药确认` | `查看照片` |
| 全部药项已确认 | `查看本次记录` | `记录异常` |
| `missed` | `补充实际记录` | `记录原因` |
| `revoked` | `查看修订` | 无 |

已经完成或撤销的任务从通知打开时进入只读详情，不重新打开相机，也不提供重复提交按钮。

### 3.2 整组拍摄

1. 取景框顶部显示本任务全部药项和计划量；提示 `请把本次准备的药物放在画面内。`。
2. 画质提示可显示 `光线较暗`、`画面可能模糊`、`有物体靠近画面边缘`，但手动快门始终可用。
3. 用户点击 `拍照` 后进入预览，操作 `重拍`、`保存照片`。
4. 保存时显示 `正在安全保存照片…`；只有成功后显示 `照片已保存`，并把一张照片关联到全部任务药项。
5. 保存完成后任务进入“已准备”，立即打开逐药确认；端侧分析异步进行。

保存失败弹窗：标题 `照片没有保存成功`；正文 `本次照片未写入记录。你可以重试，或说明原因后继续人工确认。`；按钮 `重试保存`、`不使用照片继续`。

### 3.3 逐药拍摄

1. 顶部显示进度“{当前序号}/{药项总数}”和当前药名、计划量。
2. 每个药项必须完成“已保存一张照片”或“已说明跳过原因”之一，才能进入下一项。
3. 已保存照片只关联当前药项；返回重拍只替换尚未提交的预览，不删除已经提交的历史照片。
4. 所有药项的照片槽位处理完毕后，任务进入“已准备”并打开逐药确认。
5. 中途退出时保留已成功保存的照片；任务仍显示“拍照未完成”，再次进入从第一个未处理药项继续。

### 3.4 跳过拍照

入口文案：`这次无法拍照`。原因单选：`相机无法使用`、`当前环境不方便`、`其他原因`。选择其他原因后可填写自由文本。

确认页：

> 本次会记录为“无照片人工确认”。你仍需逐种确认实际服用情况。

按钮：`返回拍照`、`记录原因并继续`。整组模式下原因关联全部任务药项；逐药模式下只关联当前药项。不得创建图片占位文件。

### 3.5 端侧分析的异步反馈

| 结果 | 展示 |
| --- | --- |
| 处理中 | `正在进行辅助查看，不影响继续记录。` |
| 得到计数 | `画面中检测到的物体数：{整数}`，旁注 `这不是服用量，请逐种确认。` |
| `suspected_change` | 黄色卡片 `疑似发生变化`；正文 `请人工核对照片、包装、厂家/批次和已有处方。辅助查看不能判断药物是否可以服用。` |
| `unable` | 灰色卡片 `无法判断`；正文 `本次照片仍已保存，请按照片和已有记录人工核对。` |
| `no_anomaly_signal` | 不显示结论卡片，只保留照片、可用计数和逐药表单 |

若结果在用户完成确认后返回，只在该条时间线记录上增加对应标记；不改变确认、库存或任务完成状态。

半片、破损片、透明胶囊、严重遮挡/重叠、同一种药的新旧外观并用、没有当前基准、模型错误、超时或设备不支持均使用“无法判断”路径；整组多种药同框不自动进入该路径。首版不显示尺寸变化原因。

## 4. 已准备与逐药确认

### 4.1 已准备页首

固定状态条：`已准备·待确认`。

固定解释：`照片或跳过原因已经保存，但这还不表示你已经服用。请逐种填写实际情况。`

本页不提供“一键全部按计划服用”。每个药项必须分别操作；底部按钮只保存已选择的逐药事实，绝不批量赋值。

### 4.2 药项确认卡

每张卡显示药名、计划量、关联照片状态和三个互斥选项：

- `按计划量服用`：实际量预填计划量；用户点击 `确认此药` 才提交。
- `与计划量不同`：展开实际量输入框；数量必须大于 0，且不得等于计划量，否则提示选择恰当状态。
- `未服用`：实际量显示 0；点击 `确认此药` 提交。

提交前确认行：`你记录的实际量：{数量}{单位}`。提交后卡片只读，显示确认时间，并提供 `修订这项记录`。单个药项提交即在同一事务中追加相应库存流水；其他药项保持待确认。

页面底部：

- 尚有待确认项：按钮 `稍后继续`，提示 `还有 {n} 种药待确认，本次任务不会标为完成。`。
- 全部药项已提交：按钮 `完成本次记录`。该按钮只结束页面并派生任务状态，不改变任何药项选择。

### 4.3 正常、晚服和部分完成

- 在正常记录截止时间前完成全部药项且至少一项实际量大于 0，任务显示“已完成记录”；这只表示逐药确认流程完整，不表示每种药都按计划服用。
- 正常记录截止后、最晚记录时间前进入页面，置顶提示 `已超过你设置的正常记录时间，完成后会标记为晚于正常时间记录。`；全部药项完成且至少一项实际量大于 0 时，任务显示“晚于正常时间记录”。
- 多药中仅一部分已提交时，任务卡显示“{已确认数}/{总数} 项已确认”，生命周期不进入最终完成状态。
- 到最晚记录时间仍有待确认项，为这些药项追加漏服事实，任务投影为 `missed` 并显示“本次未完成服用记录”；已经提交的药项事实和库存不变。
- 若全部药项均明确选择“未服用”，任务投影为 `missed`，页面显示“全部药项记录为未服用”，不等待最晚记录时间。

## 5. 漏服、补录、疑似重复与异常

### 5.1 漏服后补录

漏服详情固定说明：`系统曾在 {record_until} 记录本次尚未完成。补充记录会保留这条历史，不会把它删除。`

操作 `补充实际记录` 后：

1. 用户填写实际服用时间；不得晚于当前时间。
2. 仅对仍未确认药项逐项选择按计划量服用、与计划量不同或未服用。
3. 提交页显示 `将添加一条补充记录，并保留原来的漏服记录。`
4. 提交后创建修订关系和相应库存流水，时间线标签为 `漏服后补录`。

若用户实际上未服用，可选择 `记录原因为未服用`，只补充原因，不产生库存变化。

### 5.2 不确定是否已服与疑似重复

入口位于任务详情和“记录异常”。选择 `不确定是否已服` 时，先展示当日照片时间线、拍摄时间和逐药人工确认记录，固定提示：`这里只显示已有记录，App 不能替你判断是否已经服用。`

若用户选择 `记录疑似重复`，填写发生时间、关联药项、症状（可选）、原因和自由文本。保存后显示：

> [医学审核文案占位：通用求助与紧急分流；不得包含补服、加倍、停药、抵消、改量或等待 App 判断的建议。]

按钮占位固定为 `查看经审核的求助说明`、`返回记录`；真实患者版本启用前必须由医学负责人按适用范围签署内容和外部求助入口。

### 5.3 副作用及其他异常

异常类型：晚服、漏服、缺药、疑似重复、不确定是否已服、副作用、医嘱暂停。表单字段为时间、关联任务、关联药项、原因、症状和自由文本。自由文本明确标记“仅保存在本机，不进入默认研究包”。

副作用保存后仅展示同一医学审核占位模块。缺药记录不会把过去任务改成已服用；药到后用户从新的计划任务继续。

## 6. 纠错、撤销与照片删除

### 6.1 修订单个药项

从时间线选择 `修订这项记录`，页面并列展示“原记录”和“新记录”。用户选择修订原因，重新填写药项状态、实际量和实际时间。

确认弹窗：

- 标题：`确认修订这项记录？`
- 正文：`原记录会保留。库存将通过新的反向和修订流水重新计算。`
- 按钮：`返回检查`、`确认修订`。

成功后时间线将两条事实通过“已由此修订”连接，余额显示重算结果。

### 6.2 撤销确认

仅对错误创建且不需要替代事实的确认使用。确认弹窗：

- 标题：`撤销这项服用记录？`
- 正文：`原记录不会被删除；系统会添加等量反向库存流水，并标记为已撤销。`
- 按钮：`取消`、`确认撤销`。

撤销完成后不得从原任务再次一键重放；需要新事实时走“修订”流程。

### 6.3 永久删除照片

照片详情操作 `永久删除照片` 后二次确认：

- 标题：`永久删除这张照片？`
- 正文：`原图和缩略图将被删除，之后无法在 App 中恢复。拍摄时间、删除时间和“照片已删除”标记会保留。服用记录和库存不会改变。`
- 按钮：`保留照片`、`永久删除`。

成功状态：`照片已永久删除`。原图区域替换为墓碑，不留模糊预览。

## 7. 记录、库存与事项

### 7.1 时间线

每条记录按时间显示：计划时间、拍摄/跳过时间、照片状态、逐药计划量、逐药实际量、确认时间、端侧异常标记、异常、修订和删除时间。计数单独位于“照片辅助信息”，不得放入实际量列。

筛选仅作用于展示，不改变事实。无照片显示 `本次无照片·{原因类别}`；分析失败显示 `辅助查看未完成`；墓碑显示 `照片已永久删除·{时间}`。

### 7.2 库存

库存卡显示“预计余额”和“预计用尽日”，固定脚注：`根据你录入和逐药确认的数量估算。丢失、破损或未记录变化会造成偏差。`

人工修订库存必须填写原因和新盘点量；系统生成差额流水而不是覆盖历史。缺药卡操作为 `记录缺药`、`修改补药提醒`，不得自动改变过去任务。

### 7.3 复诊、取药和检查事项

事项由用户按已有医嘱手工新增、编辑和完成。复诊日显示卡片：`请核对处方是否有变化。` 操作 `处方无变化`、`录入新处方版本`。前者只记录用户核对动作，后者进入处方版本流程。

本地摘要展示处方版本、逐药确认、晚服/漏服、缺药、副作用和库存问题；不添加自动推荐项目或周期。

## 8. 隐私设置与数据权利

### 8.1 应用锁

设置项：`使用设备锁保护 App`。开启时调用设备生物识别/PIN；失败文案 `未能验证设备凭据，数据没有被删除。` 操作 `重试`、`退出 App`。不提供独立可找回密码。

### 8.2 截屏与录屏

敏感页面默认阻止。全局放开前弹窗：

- 标题：`允许截屏和录屏？`
- 正文：`处方、药物和照片可能被其他应用或旁人看到。此设置会应用到所有敏感页面。`
- 按钮：`继续保护`、`允许`。

偏好只保存在本机并写审计记录。

### 8.3 照片保留

选项：`长期保存（默认）`、`保存 {期限}`。更改期限的说明：`新期限用于之后的自动清理；你主动删除的照片会立即永久删除。` 自动到期前在设置页显示预计清理数量，保留墓碑。

### 8.4 研究包导出

流程：范围说明 → 字段预览 → 授权确认 → 本机生成 → 调用系统分享面板。预览固定列出默认排除项：照片、处方原图、药名、疾病、自由文本和稳定设备标识。

未授权时不生成文件。授权确认文案：`我已查看导出范围，并同意本次生成脱敏研究包。` 生成后写本地审计；App 不预选上传目的地。

### 8.5 清除研究事件与全部数据

- `清除研究事件`：说明不会删除处方、照片、服药或库存事实；确认后只清除本机研究事件。
- `清除全部本机数据`：要求再次验证设备凭据并输入页面随机显示的确认词。正文明确 `处方、照片、服药记录、库存、事项、诊断信息和密钥都会被销毁，当前版本无法恢复。`
- 清除完成后回到首次设置，不保留上次患者摘要。

## 9. 错误与恢复文案

| 场景 | 标题 | 系统与用户操作 |
| --- | --- | --- |
| 相机权限拒绝 | 无法使用相机 | `打开系统设置`或`说明原因并继续`；后者保存跳过状态 |
| 照片加密保存失败 | 照片没有保存成功 | 不进入已准备；`重试保存`或`不使用照片继续` |
| 存储空间不足 | 空间不足，照片未保存 | 不显示已保存；`查看照片保留设置`或`不使用照片继续` |
| 模型错误/超时 | 无法判断 | 照片保留，逐药确认继续 |
| 任务提交失败 | 本次记录没有保存 | 整个事务回滚；显示 `重试`，不得出现部分库存扣减 |
| 密钥不可用 | 暂时无法打开本机记录 | 不建明文库、不静默清空；只提供经安全评审的恢复说明 |
| 通知权限关闭 | 提醒权限已关闭 | 今日任务继续可用；提供系统设置入口 |
| 时区或系统时间变化 | 请核对计划时间 | 暂停自动派生，逐方案确认后重建未来任务与提醒 |
| 端侧能力关闭 | 辅助查看当前不可用 | 不请求联网，照片与人工确认继续 |

## 11. 原型与可用性验收清单

1. 整组照片可关联三个药项，但不存在一次点击替三个药项赋值的控件。
2. 逐药模式可中途退出和恢复；每个药项照片/跳过状态独立。
3. 照片保存失败时不出现“已准备”；模型失败时仍可完成人工确认。
4. 两种药按计划、一种药与计划量不同，三个实际量和库存变化逐项对应。
5. 0.5 片只出现在计划/实际量；物体计数保持整数或空。
6. 半片、破损片、透明胶囊和同一种药的新旧外观并用都显示“无法判断”；整组多种药同框不因此回退。
7. 正常截止和最晚记录时间分别产生晚服提示与漏服事实；补录保留原事实。
8. 从已完成任务通知打开只能查看，不可重复扣库存。
9. 修订和撤销都展示原事实、关系及反向库存影响。
10. 删除照片后没有原图或缩略图预览，时间线仍有墓碑。
11. 锁屏不显示药名、剂量、疾病、异常或服用结果；敏感页默认无法截屏。
12. 飞行模式和端侧能力关闭时，可完成建档后的全部人工主链。
13. 研究包只有预览并主动授权后生成，默认排除基线规定的敏感字段。
14. 所有异常分流在专业签署前均显示为审核占位，不生成个体化处置内容。
