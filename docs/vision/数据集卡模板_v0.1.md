## 4. 单样本 schema

数据 manifest 中每张照片至少包含下列字段；业务药名、疾病和处方文本不应出现在机器学习 manifest：

```json
{
  "sampleId": "<uuid>",
  "sourceId": "SRC-001",
  "assetSha256": "<64 lowercase hex>",
  "captureMode": "group",
  "appearanceVersionGroupId": "<pseudonymous-group-id>",
  "captureSessionId": "<pseudonymous-session-id>",
  "participantGroupId": null,
  "deviceTier": "D-M",
  "deviceModelCode": "<coded value>",
  "androidApi": 30,
  "objectCountGold": 3,
  "countEligible": true,
  "appearanceGold": "no_change",
  "appearanceReasons": [],
  "qualityFlags": [],
  "supportFlags": ["whole_opaque_supported"],
  "lighting": "indoor_even",
  "background": "light_plain",
  "split": "frozen_test",
  "labelVersion": "labels-1",
  "consentOrLicenseRef": "<version>",
  "retentionUntil": "<YYYY-MM-DD or approved-indefinite>",
  "createdAtUtc": "<ISO 8601>"
}
```

规则：

- `assetSha256` 对原始受控资产计算；增强样本另有新 ID、父样本 ID、变换参数和哈希。
- `appearanceVersionGroupId` 是随机化研究标识，不得是药名、批准文号或可逆编码。
- `participantGroupId` 仅用于防泄漏；不需要时为空，不得使用广告 ID、IMEI 或稳定硬件标识。
- `objectCountGold` 是物理对象整数，不是剂量；无法可靠计数时 `countEligible=false` 并记录质量原因。
- 患者原图不得进入 Git；仓库只保存无敏感内容的 schema、哈希和合成黄金向量。

## 5. 采集协议

### 5.1 参考基准图

- 每个外观版本至少一张正面、一张背面，来自同一已确认外观版本。
- 使用 App 目标相机流程和相同加密/解密路径采集，不使用经过美化或去背景的替代图作为唯一基准。
- 记录设备、方向、光线和包装/批次备注是否由用户确认；模型数据 manifest 不保存包装文字。
- 半片、破损、透明胶囊或同药混用可拍照建档，但标为强制回退，不能成为受支持外观基准。

### 5.2 消费级照片

- 整组和逐药均使用手动快门，不通过自动挑帧制造比真实流程更好的数据。
- 每个支持外观版本至少跨 3 次拍摄会话、2 种背景、3 种光线和 2 台设备；同一连拍不能计作独立会话。
- 整组照片包含 1–8 个物体并覆盖多种计划药物；不同药物共存不标为同药混合外观。
- 困难样例按受控方案采集，不以模糊、遮挡等低质量增强完全代替真实拍摄。

### 5.3 变化与相似外观压力样例

- 优先使用同一药物经确认的不同外观版本；无法获得时，可用合法来源的不同外观实体做视觉压力测试，但必须标为非临床替代。
- 四类差异分别采集：颜色、形状、纹理、刻印；刻印只标视觉变化，不转录字符。
- 相似外观样例需盲法标注。人眼不能稳定区分时标为 `ambiguous`，预期 `unable`。
- 禁止使用数字绘图直接改变药片颜色或刻印后，把合成图当成真实效果主证据；此类图只能用于软件路径或单元测试。

### 6.2 标注项

- 实物数、完整/半片/破损/透明状态。
- 触边、遮挡、重叠、反光、暗、曝、糊。
- 与 active 基准的 `no_change | clearly_changed | ambiguous | not_applicable`。
- 明显差异原因：`color | shape | texture | imprint`，可多选。
- 整组内是否存在同一药物多个外观版本。
- 是否含手、脸、处方、包装文字、地址、姓名或其他可识别内容。

### 6.3 一致性与裁决

- 计数不一致、支持域不一致或外观标签不一致都进入第三人裁决。
- 冻结前计数完全一致率需 ≥98%，外观 Cohen's kappa 需 ≥0.80。
- 保存初始标注、裁决标签、原因码和时间，禁止覆盖原始意见。
- 标注者若能看到药名或处方，应在卡中说明偏倚；外观变化冻结测试应尽可能盲化身份信息。

## 7. 去重、分区与泄漏检查

### 7.1 去重

- 使用文件 SHA-256、感知哈希和嵌入近邻三层检查；候选近重复由人工复核。

## 8. 隐私、敏感性与安全

### 8.1 数据分类

| 数据 | 是否可能敏感 | 当前控制 |
| --- | --- | --- |
| 药片照片 | 是，可透露用药线索 | 加密、最小访问、不得公开 |
| 包装/处方文字 | 高 | 视觉数据集默认排除；误入即隔离 |
| 手部/家庭背景 | 可能 | 采集引导、裁剪、访问控制；不得声称完全去标识 |
| 设备/会话 | 可能形成指纹 | 使用分档/随机码，禁止稳定硬件标识 |
| 嵌入 | 可能泄露来源特征 | 按敏感派生数据处理，不公开默认分发 |
| 标签与理由 | 可能关联药物线索 | 随机外观组 ID，去除药名和疾病 |

### 8.2 访问与审计

- 最小角色访问；记录访问人、时间、用途、导出和删除。
- 训练环境不得自动同步到个人云盘，不接远程实验跟踪服务。
- 临时明文、缓存、缩略图和失败导出有清理 SOP；清理失败作为安全事件。
- 数据集 manifest 不含密钥、绝对患者文件路径或自由文本。
