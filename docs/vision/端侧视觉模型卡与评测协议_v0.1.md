# 长期用药管理 APP｜端侧视觉模型卡与评测协议

> 本文冻结端侧视觉的任务、输入输出、阈值选择、评测、发布和回退契约。它不是模型已达到效果门槛的声明，也不替代真实患者研究前的伦理、医学、隐私和安全签署。若本文与离线 MVP 冲突，以离线 MVP 为准。

## 0. 执行结论

1. 视觉是可完全关闭的辅助模块；照片留存和逐药人工确认不依赖它。
2. P0 只做四件事：画质门控、药片样实物总数、个人当前基准内的疑似外观变化、可靠回退。
3. `detected_object_count` 是照片级非负整数或空，不是计划量、实际服用量，也不能驱动库存。
4. 用户可见视觉状态只有 `suspected_change` 与 `unable`；`no_anomaly_signal` 仅存于内部观察和研究指标。
5. 半片、破损片、透明胶囊、同一药物新旧外观混用必须返回 `unable`；严重遮挡、重叠、无当前基准、模型/清单异常也必须回退。
6. 整组照片中存在多种计划药物是正常场景，不等于“混合外观”；强制回退所称混用，特指同一药物同时使用多个厂家、批次或外观版本。
7. P0 不输出药名、成分、真伪、剂量、可否服用或吞服事实，不做开放世界药片身份识别。
8. 模型、预处理、阈值和输出 schema 作为一个不可拆分版本随安装包发布；历史观察不随升级重算。
9. 任一子任务未达门槛，只关闭该子任务或整个视觉模块，不改用联网推理，也不阻断人工主链。

## 1. 预期用途与明确禁用

### 1.1 预期用途

- 在已加密保存的服药照片上离线运行。
- 提示拍摄画质可能不足。
- 统计画面中可见、可分离的药片样物体总数。
- 在用户已经建立单一当前外观基准时，对本次画面与该基准做封闭范围比较。
- 在无法可靠辅助时明确回退，让用户继续人工核对。
- 为本机研究事件提供模型版本、耗时、计数、回退类别和结果类别。

### 1.2 禁用用途

- 不从照片推断药名、药品身份、成分、厂家、批次或真伪。
- 不把检测到的物体数换算为片、粒、半片等处方剂量。
- 不判断本次准备是否符合处方，不判断用户是否已经吞服。
- 不自动填写 `planned_dose_quantity` 或 `confirmed_consumption_quantity`。
- 不改变 `DoseLifecycle`、`ItemConsumptionAssertion`、库存流水、处方或异常处置。
- 不输出个体化服药、补服、停药、加倍或求医建议。
- 不对相册、任意未关联照片、处方照片或药物外包装运行本管线。
- 不上传照片、特征、模型输出或诊断到服务器。

## 2. 任务与输出契约

### 2.1 管线顺序

```text
已加密保存的 captured 照片
  → 在受控内存中解密
  → manifest 与运行时自检
  → 确定性强制回退检查
  → 画质门控
  → 药片样物体检测和总数
  → 当前外观基准可用性检查
  → 封闭范围外观差异评分
  → suspected_change | unable | no_anomaly_signal
  → 追加不可变 VisionObservation
  → 清除推理缓冲区
```

`skipped_with_reason` 没有图像，因此不得创建伪造的视觉观察，也不得用 `unable` 代替照片状态。

### 2.2 画质门控

画质门控至少计算以下不含健康语义的指标：

| 代码 | 含义 | 行为 |
| --- | --- | --- |
| `quality_too_dark` | 主体区域亮度不足 | 外观 `unable`；计数仅在计数门独立通过时可输出 |
| `quality_overexposed` | 主体区域高光裁切过多 | 同上 |
| `quality_blur` | 主体边缘清晰度不足 | 同上 |
| `quality_edge_cutoff` | 物体触碰裁剪边缘，可能未完整入镜 | 外观 `unable`；计数置空 |
| `quality_glare` | 反光覆盖关键颜色、纹理或刻印区域 | 外观 `unable`；计数可独立判断 |
| `occlusion` | 物体被手、包装或其他物体明显遮挡 | 外观 `unable`；计数置空 |
| `overlap` | 两个或更多药片样物体明显重叠 | 外观 `unable`；计数置空 |

质量提示不得阻止用户手动快门或照片保存。阈值由第 7 章的校准流程产生并写入 manifest，不能在运行时远程修改。

### 2.3 实物计数

- 输出字段固定为 `detected_object_count: number | null`。
- 支持对象仅为画面中完整可见、彼此可分离的口服片剂或胶囊外形物体。
- P0 支持范围：逐药照片 1–4 个物体，整组照片 1–8 个物体；超出范围返回空计数并回退人工。
- 半片或破损片可作为一个可见物体被检测，但必须同时使外观结果为 `unable`；页面仍须强调计数不是服用量。
- 透明胶囊若边界足够清晰可输出计数，但外观结果固定为 `unable`。
- 不把计划剂量作为检测先验，不以“应该有几个”修正计数，不把计数分配给具体药项。
- 整组照片只输出总数，不要求药项分类；逐药照片也不得把总数回填为实际服用量。

### 2.4 外观变化

外观比较只允许使用本次任务所关联药物的 active `MedicationAppearanceVersion`：

- 逐药模式：本次物体只与当前药项的正/背面基准比较。
- 整组模式：物体只与当前任务内各药物的 active 基准集合比较，可输出整组级异常；不得向用户声称定位到具体药项。
- 若整组内存在多个近似基准而无法稳定分配，返回 `unable(ambiguous_group_assignment)`。
- 对刻印只比较视觉差异，不识别或输出字符。
- `size` 不进入 P0 领域原因枚举：没有尺度参照和受控拍摄距离时，不得输出尺寸变化原因。未来启用必须新增带实体尺度参照的交互、契约主版本和独立 ADR。

允许的 P0 内部原因：`color | shape | texture | imprint`。`suspected_change.reasons` 必须是去重、非空数组；任何原因都只是差异线索，不是身份判断。

### 2.5 状态语义

```ts
export type VisionUnableReasonCode =
  | 'model_disabled'
  | 'manifest_invalid'
  | 'model_unavailable'
  | 'unsupported_device'
  | 'input_decode_error'
  | 'media_unavailable'
  | 'timeout'
  | 'nonfinite_output'
  | 'unsupported_half'
  | 'unsupported_damaged'
  | 'unsupported_transparent_capsule'
  | 'mixed_appearance_same_medication'
  | 'no_active_baseline'
  | 'quality_edge_cutoff'
  | 'occlusion'
  | 'overlap'
  | 'quality_too_dark'
  | 'quality_overexposed'
  | 'quality_blur'
  | 'quality_glare'
  | 'ambiguous_group_assignment'
  | 'score_in_reject_band'
  | 'object_count_out_of_range';

export type AppearanceAssessment =
  | {
      status: 'suspected_change';
      reasons: Array<'color' | 'shape' | 'texture' | 'imprint'>;
    }
  | { status: 'unable'; reasonCode: VisionUnableReasonCode }
  | { status: 'no_anomaly_signal' };
```

| 状态 | 产生条件 | 用户界面 | 后续行为 |
| --- | --- | --- | --- |
| `suspected_change` | 至少一个启用的差异分数超过预先冻结的高阈值，且没有更高优先级回退原因 | 黄色“疑似发生变化”卡片 | 人工核对继续；不改变确认或库存 |
| `unable` | 强制回退、质量不达标、分数落入拒绝区间或技术失败 | 灰色“无法判断”卡片 | 照片保留，人工核对继续 |
| `no_anomaly_signal` | 所有适用分数均低于预先冻结的低阈值，且全部门控通过 | 不生成结果卡片 | 只保存内部观察；逐药确认照常进行 |

低阈值与高阈值之间必须是拒绝区间，不能通过四舍五入或默认值强制落到另外两类。

### 2.6 强制 `unable` 与优先级

当存在多个原因时，`unable_reason_code` 按下列顺序取第一个；完整诊断只进入脱敏的本地限额日志，不进入用户文案或研究包自由文本：

```text
model_disabled
manifest_invalid
model_unavailable
unsupported_device
input_decode_error
media_unavailable
timeout
nonfinite_output
unsupported_half
unsupported_damaged
unsupported_transparent_capsule
mixed_appearance_same_medication
no_active_baseline
quality_edge_cutoff
occlusion
overlap
quality_too_dark
quality_overexposed
quality_blur
quality_glare
ambiguous_group_assignment
score_in_reject_band
object_count_out_of_range
```

半片、破损片、透明胶囊和同一药物新旧外观混用由用户建档信息或人工标记触发确定性回退，模型不得覆盖。没有照片时不进入此列表。

## 3. 预处理契约 v1

同一 manifest 的参考图与消费级照片必须使用同一预处理版本；任一变化都要提升 `preprocessingVersion`，重新生成黄金向量和阈值。

1. 从密文解密到受控内存，拒绝不完整、超大或无法解码的输入；不创建持久明文副本。
2. 按 EXIF 方向旋转到视觉正向，转换到 sRGB，忽略位置、设备名称等非像素元数据。
3. 保留原图用于照片记录；仅推理副本把长边等比缩放至最多 1280 px，不做自动美化、锐化或颜色增强。
4. 检测输入固定为 RGB、`640×640`、等比 letterbox、填充值 114；通道顺序、dtype 和归一化由 manifest 精确声明。
5. 检测框采用预先冻结的置信阈值和 IoU=0.50 的 NMS；触边、重叠和遮挡标记在计数提交前执行。
6. 外观裁剪在检测框四周增加 15% padding，裁到图像边界；短边触边则回退。
7. 外观输入固定为 RGB、`224×224`、等比 letterbox；P0 默认 `float32` 且像素缩放到 `[0,1]`。
8. 正反面基准分别生成嵌入；本次裁剪与两面中较小的合规差异分数比较。基准和本次图必须引用同一 manifest 版本。
9. 推理完成后清除解码图、裁剪、张量和嵌入缓冲；持久化只保存数据契约允许的观察字段。

若最终模型输入与上述尺寸或 dtype 不兼容，必须发布新的预处理主版本和 ADR 修订，不能只改实现代码。

## 5. 数据集划分与防泄漏

### 5.1 数据单元

- `appearance_version_id` 是外观评测的最小分组单元；同一外观版本的参考图和消费级图必须可追踪。
- `capture_session_id`、设备型号、拍摄者和布景批次用于防止近重复图跨分区。
- 训练、校准、冻结测试按 `appearance_version_id` 分组，三者互斥；冻结测试中的参考图可作为个人基准输入，但其消费级图不得用于训练或阈值选择。
- 同一连拍、视频抽帧、增强变体和近重复图片只能位于同一分区。
- 若有真实参与者数据，按参与者分组，不得让同一参与者跨校准和冻结测试。

### 5.2 三类数据用途

| 分区 | 可用于 | 禁止 |
| --- | --- | --- |
| 训练集 | 拟合检测、画质和外观嵌入 | 报告最终效果 |
| 校准集 | 选择计数阈值、质量门和外观双阈值 | 训练权重；调试冻结测试 |
| 冻结测试集 | 一次性计算发布门禁和分层指标 | 调阈值、挑样本或人工修正输出 |

冻结测试开启前，必须记录数据 manifest 和模型 manifest 哈希。任何测试后调参都产生新候选版本和新的未见冻结测试集。

### 5.3 外部数据的使用限制

- NLM 挑战数据含单粒参考图与消费级图片，并覆盖多种照明；可用于单粒域外压力测试，但不能代表整组、重叠、透明胶囊或本项目拍摄交互。
- ePillID 是细粒度、低样本药片身份检索基准，能暴露相似外观困难；本项目不得把其身份类别变成 App 输出，也不得把检索指标当作本项目异常提示效果。
- 公开数据在纳入前必须逐项记录许可、下载日期、原始哈希和再分发限制；无法确认使用条件时只记录来源，不下载、不训练、不随包分发。
- 禁止从搜索引擎、电商、社交媒体或药品网站批量抓取图片作为训练/评测数据。

## 6. 标注真值与争议处理

### 6.1 计数真值

- 两名标注者独立标注完整可见药片样物体数、触边、遮挡、重叠和特殊形态。
- 计数或质量标签不一致时由第三名标注者裁决；不得用模型结果帮助裁决。
- 半片和破损片按一个物理对象标注，同时保留强制回退标签；这不代表 1 片剂量。

### 6.2 外观真值

| 标签 | 定义 |
| --- | --- |
| `no_change` | 本次物体与其已确认的同一外观版本基准配对，且无人工制造的外观变化 |
| `clearly_changed` | 与基准相比，至少两名盲法标注者独立确认存在颜色、形状、纹理或刻印中的明显变化 |
| `ambiguous` | 变化过小、反光/姿态干扰或标注者不能一致判断；期望回退，不进入正负效果分母 |
| `not_applicable` | 强制回退、无基准或技术失败；只评估回退合规性 |

“相似外观”压力样例必须来自有合法来源的不同外观版本或受控实体替换。若人眼也不能稳定确认明显变化，标签必须为 `ambiguous`，不得为了增加阳性样本强行标为 `clearly_changed`。

### 6.3 标注质量

- 计数使用完全一致率和加权 Cohen's kappa；外观二分类使用 Cohen's kappa；均报告 95% 置信区间。
- 冻结测试前要求计数完全一致率 ≥98%，外观 kappa ≥0.80；未达到则修订标注手册并重新独立标注。
- 所有裁决记录原标签、裁决人、原因码和时间；不得覆盖初始标注。

## 7. 阈值冻结方法

### 7.1 计数阈值

在校准集上遍历检测置信阈值；NMS IoU 固定为 0.50。选择满足“低估率不高于 3%、高估率不高于 3%”的候选中，计数覆盖率最高者；并列时选择更高的检测置信阈值。无候选满足时，计数子任务不得发布。

### 7.2 质量阈值

每类质量分数在校准集上独立选择，使对应严重质量样例的回退召回率 ≥95%，同时支持域清晰样例的误回退率 ≤10%。多门同时触发时按第 2.6 节优先级记录主原因。

### 7.3 外观双阈值

对每个启用原因分别选择低阈值和高阈值：

1. 高阈值用于 `suspected_change`，先满足 `no_change` 误报率门槛。
2. 低阈值用于 `no_anomaly_signal`，必须满足 `clearly_changed → no_anomaly_signal` 的不安全漏报门槛。
3. 低阈值与高阈值之间全部映射到 `unable(score_in_reject_band)`。
4. 在满足第 8 章门槛的候选中选择支持域覆盖率最高的一组；并列时选择更宽的拒绝区间。
5. 阈值只在校准集选择，冻结后才能打开测试集；不得按设备、药名、患者或单个药物临时调阈值。

## 8. 指标定义与研究前硬门槛

所有比例报告分子/分母、点估计和双侧 95% Clopper–Pearson 区间；门槛同时看总体和第 9 章规定的核心分层。下表是内部研究工程门槛，不构成医疗安全宣称。

### 8.1 画质与强制回退

| 指标 | 定义 | 门槛 |
| --- | --- | --- |
| 强制回退违规数 | 半片、破损、透明胶囊、同药混合外观未返回 `unable` 的样例数 | 0；每类冻结测试至少 100 张 |
| 严重质量回退召回率 | 严重暗、曝、糊、触边、反光、遮挡、重叠中返回 `unable` 的比例 | 总体 ≥95%；每类 ≥90% |
| 支持域误回退率 | 清晰且受支持样例被质量门回退的比例 | 总体 ≤10%；每核心分层 ≤15% |

### 8.2 实物计数

只在人工真值为支持域且模型输出非空计数的样例上计算准确性，同时单独报告覆盖率。

| 指标 | 定义 | 门槛 |
| --- | --- | --- |
| 计数覆盖率 | 输出非空计数 / 支持域照片 | 总体 ≥80%；每核心分层 ≥70% |
| 完全一致率 | `detected_object_count == gold_count` | 总体 ≥95%；每核心分层 ≥90% |
| 平均绝对误差 | `mean(abs(pred-gold))` | 总体 ≤0.10 |
| 低估率 | `pred < gold` | 总体 ≤3% |
| 高估率 | `pred > gold` | 总体 ≤3% |

计数失败只关闭计数展示，不能阻止外观子任务在其独立条件满足时运行，也不能影响人工确认。

### 8.3 外观变化

| 指标 | 定义 | 门槛 |
| --- | --- | --- |
| 不安全漏报率 | `clearly_changed` 被输出为 `no_anomaly_signal` | 总体点估计 ≤2%，且单侧 95% 上界 ≤5%；每核心分层 ≤5% |
| 疑似变化召回率 | `clearly_changed` 被输出为 `suspected_change` | 总体 ≥70%；每核心分层 ≥60% |
| 正常样例误报率 | `no_change` 被输出为 `suspected_change` | 总体 ≤10%；每核心分层 ≤15% |
| 支持域拒绝判断率 | 支持域中输出 `unable` 的比例 | 总体 ≤25%；每核心分层 ≤35% |
| 内部无异常信号精确率 | 所有 `no_anomaly_signal` 中真值为 `no_change` 的比例 | 总体 ≥95% |

`unable` 不计作不安全漏报，但计入拒绝判断和人工回退。不能通过让所有样例回退来满足漏报门槛。

### 8.4 人工回退

```text
overall_manual_fallback_rate =
  (forced_unable + quality_unable + technical_unable + reject_band + user_manual_override)
  / captured_photos

supported_manual_fallback_rate =
  (quality_unable + technical_unable + reject_band + user_manual_override)
  / supported_domain_photos
```

- 总体人工回退率只报告，不设上限，因为特殊形态被有意纳入。
- 支持域人工回退率在代表性冻结测试中必须 ≤35%。
- 必须按原因报告，禁止把技术失败并入“用户选择人工”。

### 8.5 端侧性能与稳定性

在 Phase 0 的 D-L、D-M、D-N、D-C 真机上，CPU 后端预热 5 次、正式运行 30 次，报告 P50/P95/max：

| 指标 | 门槛 |
| --- | --- |
| 模型冷加载 P95 | ≤1.5 s |
| 从解密开始到观察提交的端到端 P95 | ≤3 s；超时稳定返回 `unable` |
| 额外峰值 RSS | ≤256 MiB 且 ≤设备物理内存的 20% |
| 30 次连续运行 | 0 崩溃、0 ANR、0 非有限输出、0 网络请求 |
| 分类与计数一致性 | 同一黄金输入在四类设备上状态和整数计数 100% 相同 |
| 持续运行退化 | 后 10 次推理 P95 相对前 10 次增加不超过 30% |

任一机型因兼容、内存或性能失败时，该机型的相应视觉能力默认关闭；不能抬高超时来遮蔽失败。

## 9. 必测分层与样例矩阵

### 9.1 核心分层

每个指标必须至少按以下维度分层；单元格样本不足时标为“证据不足”，不能并入总体后宣称通过：

- 拍摄模式：整组、逐药。
- 物体数：1、2–4、5–8。
- 光线：室内均匀、低照、暖色光、冷色光、侧光、高反光。
- 背景：浅色纯色、深色纯色、纹理背景、与药片近色背景。
- 设备：D-L、D-M、D-N、D-C；前后摄像头版本只支持后摄像头，前摄需回退。
- 外观：圆/椭圆/异形片，实色胶囊，不同颜色、纹理和刻印清晰度。
- 困难因素：触边、遮挡、重叠、反光、运动模糊、相似外观、换批次。

### 9.2 场景预期

| 场景 | 计数 | 外观状态期望 |
| --- | --- | --- |
| 清晰逐药、同一 active 基准 | 整数 | `no_anomaly_signal` 或校准拒绝；用户不见肯定结论 |
| 清晰逐药、明显颜色/形状/纹理/刻印变化 | 整数 | `suspected_change` 或保守 `unable`；不得输出内部无异常信号 |
| 清晰整组、多种计划药物、彼此分离 | 总数 | 允许整组异常；无法稳定比较则 `unable` |
| 与某个基准极相似但来源不同的压力样例 | 整数 | 按盲法真值评估；歧义样例应 `unable` |
| 半片 | 可选整数 | 强制 `unable(unsupported_half)` |
| 破损片 | 可选整数 | 强制 `unable(unsupported_damaged)` |
| 透明胶囊 | 可选整数 | 强制 `unable(unsupported_transparent_capsule)` |
| 同一药物新旧厂家/批次同时使用 | 不要求 | 强制 `unable(mixed_appearance_same_medication)` |
| 无 active 基准 | 可选整数 | 强制 `unable(no_active_baseline)` |
| 严重遮挡、重叠或触边 | 空 | 强制 `unable` |
| 模型缺失、损坏、超时、NaN | 空 | 稳定 `unable`，照片和人工主链继续 |

### 9.3 黄金集最低规模

黄金集与最终冻结测试可以重叠，但不得与训练或校准重叠；最低包含：

- 支持域 `no_change`：逐药 150 张、整组 150 张。
- `clearly_changed`：逐药 150 张、整组 150 张，四个启用原因均不少于 75 张，可多标签。
- 强制回退：半片、破损片、透明胶囊、同药混合外观各 100 张。
- 严重质量：暗、曝、糊、触边、反光、遮挡、重叠各 75 张。
- 技术故障黄金向量：模型缺失、哈希错误、形状错误、NaN、超时各 20 次。
- 四类真机各运行相同的最小黄金子集 100 张，覆盖三种状态与 1–8 个物体。

允许样例同时属于多个困难分层，但总样本量、每层独立样本数和交叉重叠必须在评测报告中透明列出。

## 10. 发布门禁、降级与回滚

### 10.1 独立发布判定

| 判定 | 条件 | 运行行为 |
| --- | --- | --- |
| `disabled` | manifest/运行时硬门槛失败，或两个子任务均未通过 | 不运行模型；照片和人工确认继续 |
| `count_only` | 画质与计数通过，外观未通过 | 只显示物体总数；外观观察统一 `unable(model_disabled)` |
| `count_and_appearance` | 画质、计数、外观和设备性能全部通过 | 按本文完整运行 |

若计数未通过但外观通过，P0 仍使用 `disabled`，不发布“appearance_only”组合，以减少未经验证的管线分支。

### 10.2 硬阻断

以下任一项发生，候选 manifest 不得进入真实患者内部研究：

- 强制回退出现一次违规。
- 冻结测试数据泄漏、来源/同意不清或测试后调参。
- 出现模型结果改写服药事实、剂量或库存的路径。
- 用户界面出现肯定性模型结论或把计数称作实际服用量。
- 模型、阈值、预处理或黄金集缺少哈希和版本。
- 运行时下载模型、阈值或动态代码，或核心流程产生网络请求。
- 任何目标设备崩溃、ANR、明文照片残留或模型失败阻断人工主链。

### 10.3 回滚

- 视觉功能必须有本地构建配置和本地安全开关，不依赖远程配置。
- 发现回归后发布新的签名安装包，将 `releaseDecision` 设为 `disabled` 或 `count_only`。
- 历史观察保留原 manifest 版本，不重新解释；UI 可隐藏已撤回模型的结果卡，但必须保留照片和人工事实。
- 回滚演练覆盖升级前、升级后、模型关闭和数据库中存在旧观察四种状态。

## 11. 评测报告固定结构

每个候选模型必须生成不可修改的报告，至少包含：

1. 模型卡版本、manifest、模型哈希、代码 commit、依赖锁文件和构建 APK 哈希。
2. 数据集卡、分区 manifest、许可/同意、去重方法和数据哈希。
3. 预处理、阈值校准记录、冻结时间和测试集首次开启记录。
4. 总体及全部核心分层的混淆矩阵、计数指标、回退率、置信区间。
5. D-L/D-M/D-N/D-C 的原始 30 次性能样本和汇总。
6. 所有门槛的通过/失败/证据不足结论，不得只报告平均值。
7. 失败样例目录：只用脱敏 ID、标签、输出、原因和受控访问位置，不把患者照片复制进报告。
8. 与上一 manifest 的回归比较和是否允许升级。
9. 视觉、QA、产品、隐私和医学边界签署状态。

## 13. 发现的基线解释点

1. 基线中的“混合外观”若不限定对象，会与合法的整组多药照片冲突。本文冻结为“同一药物新旧厂家/批次/外观版本混用”才强制回退；不同计划药物共同入镜不自动回退。
2. 当前交互没有实体尺度参照，无法稳定比较绝对尺寸。`size` 已从 P0 领域原因枚举移除；未来启用需统一修订 MVP、交互、数据契约和 ADR。
3. 数据契约只保存一个 `unable_reason_code`。本文给出确定性优先级；多原因只进入脱敏本地诊断，不扩展现有数据库字段。
