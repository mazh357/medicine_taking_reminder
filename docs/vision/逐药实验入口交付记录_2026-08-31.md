# 逐药实验入口交付记录

版本：App 0.2.0／视觉模块 0.2.0 · 更新日期：2026-09-01

状态：代码、自动化、x86_64模拟器及双架构APK验证完成；ARM64实机和药片图片评测待完成。仅限虚构数据内部测试。

## 使用入口

设置 → 照片比较实验 → 创建匿名样本 → 分别拍正面与背面 → 激活基线 → 拍照分析。

每面仅放一个完整对象；分析照片可放同一样本的1—8个对象。半片、破损、透明、混批、遮挡、反光或无法确定时选择人工回退。当前 UI 不识别药名，不连接服药事实或库存。

支持新批次版本、重拍追加、原图重试分析、逐对象人工标注、照片预览及删除。删除记录保留墓碑，物理删除失败保留重试标志。删除活动基线照片将停用基线。

## 模型与接口

统一使用独立模块契约，删除了原主 App 的平行候选数组。图片内容与嵌入张量不经过 JS；宿主只提供自有 FileProvider 的短期解密引用。

模型为 Google 官方 MediaPipe MobileNetV3-small FLOAT32 v1，文件4,117,670字节，内嵌许可明确为 Apache-2.0。完整许可随 APK 模型资源分发。

- 来源：[固定版本权重](https://storage.googleapis.com/mediapipe-models/image_embedder/mobilenet_v3_small/float32/1/mobilenet_v3_small.tflite)，访问日期2026-08-31。
- SHA-256：`bbbb4c51a55a53905af1daec995ca1aae355046f8839bb8c9f5ce9271394bc40`。
- 输入 `[1,224,224,3]`，输出 `[1,1024]`；预处理为方向校正、轮廓裁剪和RGB除以255。
- 权重可分发不等于药片任务已批准。阈值仍为未使用模板，`approvedForClosedSetUse=false`、`thresholdsApproved=false`，用户路径保持 `count_only`。
- 远程 Provider 关闭；没有服务地址、令牌、上传或遥测。

本地依赖包位于 `vendor/medication-vision-module-0.2.0.tgz`，SHA-256：`01c4fe464791732a48532334dbfbdd80fd0cd6bce546141454e92d9cd50cbd1d`。包内包含模型和源代码，不依赖本机兄弟目录。

## 数据与稳定性

- SQLCipher schema v4→v5 只追加五张视觉表，保留所有原用药数据；共用连接的事务已串行化。
- 照片仍使用AES-GCM；首次和重拍共用暂存、加密、清理流程。数据库提交失败删除新密文，不删除旧照片。
- 模型加载、推理、关闭串行；3秒超时只停止接收结果，不假定能强行中断原生调用。后台/页面退出后迟到结果不能写入。
- 主 App 的原拍照、逐药确认、库存和提醒流程不改走视觉实验。
- 修复了预生成原生目录中的 Release 离线限制无法在重新 prebuild 后保留的问题：现由配置插件持久生成禁止联网的 Release manifest。

## 不得替代的后续门禁

1. 尚无授权、独立的药片评测图片集，不能把模板阈值或通用图像推理烟测当成药片准确率证据。
2. 部分不支持场景依赖用户选择回退，自动画质检测并不完备。
3. ARM64包已构建并通过静态审计，但真实手机尚未连接，需验证相机、加密预览、内存与后台释放。
4. 带真实受控测试物品的完整基线激活、逐对象标注与图片评测仍需补测；原用户旧沙箱的初始化问题未做专项修复。真实v3→v5升级也没有本轮设备证据。
5. `realPatientDataAllowed=false` 保持不变；无临床或公开医疗使用准入结论。
6. R8构建有LiteRT较新Kotlin元数据兼容警告，构建成功且保留规则已进入最终配置；30次实际权重推理测试运行在原生仪器测试包，不能冒充R8优化后完整嵌入比较的设备验证。
