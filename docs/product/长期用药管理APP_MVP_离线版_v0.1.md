# 长期用药管理 APP｜MVP（离线版）

> 本文档是当前设计、开发和测试的产品范围基线。若总 PRD、技术架构或治理审计与本文冲突，以本文冻结的产品范围和医疗边界为准。

| 项目 | 决策 |
| --- | --- |
| 目标 | 验证照片记忆凭证、逐药人工确认和离线提醒是否改善长期用药记录体验 |
| 用户 | 能独立完成确认的成年口服片剂/胶囊长期用药患者 |
| 形态 | 无账号、无服务器、Android 先行的内部研究原型 |
| 核心闭环 | 手工建档→本地提醒→拍照/跳过原因→已准备→逐药确认→库存流水→回看/复诊 |
| 视觉边界 | 只做实物计数、疑似外观变化和无法判断，不输出药物或剂量正确性 |
| 运行前提 | 长期断网时，提醒、拍照、确认、库存、复诊和异常记录仍可运行 |

> **安全声明**  
> 照片只能说明用户曾准备并记录画面中的药物，不能证明吞服。端侧模型不能确认药名、成分、剂量或安全。漏服、疑似重复服用、副作用或紧急情况只做记录和通用安全分流；App 不提供补服、停药、加倍或改量建议。

# 1. 目标与范围

## 1.1 必须验证的假设

1. 通知直达相机、默认整组一张且允许说明原因跳过，能把长期拍照负担控制在可接受范围。
2. 带时间的照片与逐药确认，比单一“已服用”按钮更能帮助用户回忆当天记录。
3. 端侧实物计数和保守的外观变化提示可以提供辅助价值，同时在不确定时可靠回退人工。
4. 逐药实际数量能够支持多药、部分服用和可追溯库存。

## 1.2 P0 范围

- 无账号的本机档案和产品边界确认。
- 手工录入处方、药项、库存、计划、复诊和检查项目，并保存原图。
- 每日固定时间、每天多次和每周指定日期计划。
- 每个方案设置提醒时间、正常窗口结束和最晚记录时间。
- 本地通知、权限自检、提醒重建和中性锁屏文案。
- 默认整组一张、可配置逐药拍摄的手动快门流程。
- 无法拍照时选择原因并继续人工记录。
- 本地实物计数、疑似变化提示和无法判断。
- 已准备与已服用分离；每个药项独立确认实际数量。
- 追加式库存流水、缺药、取药、复诊和异常记录。
- 加密本地数据、应用锁引导、截屏控制、照片保留与清除。
- 本机研究指标、用户授权的脱敏研究包导出。

## 1.3 P1 范围

- 版本化加密备份及原子恢复。
- 面向用户的完整 PDF/CSV/JSON 导出。
- iOS 真机适配和跨端恢复验证。
- 更完整的设备兼容矩阵和公开测试发布流程。

P1 不得被描述为当前已有能力；加密备份/恢复是公开测试硬门禁。

## 1.4 明确不包含

- 联网、大模型、服务器识图、账号、云同步和远程配置。
- OCR、自动处方生成、药物相互作用、食物禁忌和个体化用药建议。
- 照护者、医生或药师远程访问。
- 奖励、虚拟宠物、植物成长和生成式角色互动。
- 自动快门、语音功能和专项无障碍模式。
- 按需用药、交替剂量、注射剂、滴剂或吸入剂。
- 开放式识药、药品真伪判断、服用安全判断和吞服证明。

# 2. 用户与研究前提

## 2.1 纳入条件

- 年满 18 周岁。
- 已获得明确处方或医嘱，并使用口服片剂或胶囊。
- 能理解照片和端侧模型的边界，能本人完成逐药确认。
- 真实患者参与前已经完成知情同意。

## 2.2 排除条件

- 需要按需用药或复杂交替剂量。
- 无法独立确认且需要照护者代操作。
- 当前存在需即时医疗处理的情况。
- 研究方案规定的其他医学或安全排除条件。

## 2.3 研究门禁

- 伦理审查或等价内部研究审批完成。
- 招募、排除、退出、意外事件、隐私和数据销毁流程已签署。
- 安全分流文案经过医学审核；药物相关边界经过药学审核。
- 隐私影响评估和威胁模型完成。

# 3. 核心旅程

## 3.1 首次设置

1. 用户阅读安全声明、照片用途和研究说明。
2. App 主动建议启用设备生物识别/PIN 应用锁，用户可拒绝。
3. 用户手工录入处方药项，并拍摄处方、包装和药片正反面。
4. 每种药启用一个当前外观基准；特殊形态选择“只人工确认”。
5. 用户录入总药量和固定日/周计划，并设置两个时间阈值。
6. 拍摄模式默认“整组一张”，用户可改为“逐药拍摄”。
7. 用户手工设置复诊、取药和检查事项。
8. App 请求通知权限，创建测试提醒并显示提醒健康状态。

## 3.2 正常服药

1. 锁屏显示“该记录用药了”等中性提醒，不显示药名和剂量。
2. 点击通知直达相机；用户手动快门。
3. 照片加密保存成功后，任务进入“已准备”。
4. 端侧分析异步返回实物总数，以及必要的疑似变化或无法判断提示。
5. 用户逐药填写实际服用情况和数量。
6. 按确认数量追加库存流水；时间线保存照片、时间和逐药结果。

## 3.3 无法拍照

1. 用户选择相机故障、环境不便或其他原因。
2. 保存 `skipped_with_reason`，任务可进入“已准备”。
3. 页面明确标记“本次无照片”，继续逐药确认。
4. 研究指标记录跳过类别，但自由文本不进入脱敏研究包。

## 3.4 部分服用

多药任务中，用户可对不同药项分别选择按计划服用、部分服用或未服用。部分服用必须输入实际数量；库存只扣已确认部分。未完成的其他药项保持待确认，不得被整组操作自动覆盖。

## 3.5 漏服后补录和纠错

- 到达最晚记录时间仍未完成的药项生成漏服事实。
- 后续可补充实际服用时间，派生为晚服记录，但保留原漏服事件和修订关系。
- 错误确认通过撤销和修订纠正，自动追加相反库存流水。
- 照片原图可以永久删除，但保留删除时间和墓碑。

# 5. 详细需求

## 5.1 档案和处方

### MVP-ACC-001 无账号使用｜P0

- 首次打开直接建立单患者本机档案。
- 不请求手机号、邮箱或网络登录。
- 明确卸载或设备损坏可能导致 P1 备份实现前的数据丢失。

### MVP-ACC-002 边界确认｜P0

- 首次使用必须确认照片不是吞服证明、模型不做医疗判断。
- 重大版本改变边界时重新确认并记录内容版本。

### MVP-RX-001 手工处方｜P0

- 录入药名、剂型、规格、计划量、单位、备注和可选疗程结束日。
- 拍摄处方原图；原图不自动改写结构化字段。
- 当前阶段不提供 OCR。

### MVP-RX-002 处方版本｜P0

- 修改处方创建新版本，显示变更字段。
- 历史任务继续引用原版本。
- 复诊日提醒用户核对是否有新处方。

### MVP-RX-003 暂停/停用｜P0

- 仅允许用户根据医嘱手工暂停或停用，并记录原因和时间。
- 暂停期间不创建新服药任务，保留恢复和复诊事项。

## 5.2 药物、基准和计划

### MVP-MED-001 当前基准｜P0

- 每种药仅一个当前基准，包含包装、正面、背面和厂家/批次备注。
- 更换外观时停用旧基准并新建版本。
- 新旧外观并行使用时关闭该药外观判断。

### MVP-MED-002 特殊形态｜P0

- 半片、破损片和透明胶囊允许建档。
- 这些形态只保留照片并人工确认，视觉结果固定为 `unable`。

### MVP-REM-001 固定计划｜P0

- 支持每日固定时间、每天多次和每周指定日期。
- 不支持按需服药和复杂交替剂量。

### MVP-REM-002 两个阈值｜P0

- `on_time_until` 必须晚于计划时间。
- `record_until` 必须晚于 `on_time_until` 且早于同方案下一任务时间。
- 两个阈值由用户按个人计划设置；App 不解释为医学服药窗口。

### MVP-REM-003 尽力提醒｜P0

- 数据库保存提醒意图，系统调度记录可丢弃并重建。
- 权限关闭、精确闹钟不可用、重启或调度不足时显示提醒健康告警。
- 不承诺绝对送达。

### MVP-REM-004 通知隐私｜P0

- 默认中性文案，不显示药名、剂量、疾病、异常或服药结果。
- 用户可在应用内查看详情；当前版本不提供锁屏详细模式。

## 5.3 拍照和端侧分析

### MVP-CAM-001 模式｜P0

- 默认整组一张，可按方案切换逐药拍摄。
- 整组照片通过关联表连接多个任务药项。
- 当前版本只使用手动快门。

### MVP-CAM-002 质量提示｜P0

- 在拍摄前提示过暗、明显模糊或药片超出取景框。
- 质量提示不可阻止用户手动快门和保存。

### MVP-CAM-003 先保存｜P0

- 照片成功写入加密私有存储后才显示“已保存”。
- 分析失败、超时或模型关闭不影响照片留存。

### MVP-CAM-004 跳过原因｜P0

- 允许相机故障、环境不便和其他原因。
- 跳过后显示“无照片人工确认”，不得创建伪照片记录。

### MVP-VIS-001 实物计数｜P0

- 输出 `detected_object_count`，表示画面中检测到的药片样物体数。
- 该字段为整数或空，不换算成 0.5 片等处方剂量。
- 整组照片只要求输出总数，不强制逐药归类。

### MVP-VIS-002 外观变化｜P0

- 仅在当前基准有效、形态受支持且画质达标时运行。
- 用户可见异常为“疑似发生变化”；不能定位时允许只提示整组核对。
- 未触发阈值只保存内部 `no_anomaly_signal`，界面继续要求人工确认，不显示通过结论。

### MVP-VIS-003 拒绝判断｜P0

- 画质差、遮挡/重叠、半片、破损、透明胶囊、同一种药的新旧外观混用、模型错误或超时时输出 `unable`；合法的整组多种药同框不自动回退。
- `unable` 必须显示人工核对入口，不影响后续记录。

## 5.4 两步确认与库存

### MVP-LOG-001 已准备｜P0

- 成功保存照片，或保存跳过原因后，任务进入 `prepared`。
- `prepared` 不扣库存，不表示吞服。

### MVP-LOG-002 逐药确认｜P0

- 每个药项独立选择 `taken_as_planned`、`partially_taken` 或 `not_taken`。
- 前两种必须保存 `confirmed_consumption_quantity`。
- 用户可暂时保留部分药项为 `pending`。

### MVP-LOG-003 时间线｜P0

- 展示计划、拍摄、确认、修订和删除时间。
- 展示逐药计划量与实际量，不把模型计数显示为服用量。
- 无照片、分析失败和照片已删除均有明确标记。

### MVP-INV-001 初始库存｜P0

- 支持片、粒等处方单位和小数数量。
- 初始库存由用户根据包装和实际持有量确认。

### MVP-INV-002 追加流水｜P0

- 只按逐药人工确认的实际量扣减。
- 撤销和修订通过反向流水纠正。
- 余额由流水汇总，不能只保存一个可覆盖数字。

### MVP-INV-003 用尽预测｜P0

- 根据余额和固定计划计算预计用尽日和补药提醒。
- 结果标注为估计值；缺药、丢失、破损和人工修订触发重算。

## 5.5 复诊与异常

### MVP-FU-001 手工事项｜P0

- 用户按已有医嘱录入复诊、取药和检查项目。
- App 不推荐检查项目或周期。

### MVP-FU-002 本地摘要｜P0

- 汇总处方版本、逐药确认、晚服/漏服、缺药、副作用和库存问题。
- 摘要只在本机查看；研究导出不默认包含药名或自由文本。

### MVP-EXC-001 异常类型｜P0

- 支持晚服、漏服、缺药、疑似重复、不确定是否已服、副作用和医嘱暂停。
- 允许关联任务和药项并记录时间、原因和症状。

### MVP-EXC-002 安全分流｜P0

- 只显示经过医学审核的通用求助和紧急分流文案。
- 不提供补服、加倍、停药、抵消或改量方案。

## 5.6 隐私、删除和研究

### MVP-DATA-001 私有加密｜P0

- 数据库和照片加密，照片不进入系统相册。
- 数据库、照片和密钥不得进入系统自动备份。

### MVP-DATA-002 照片保留｜P0

- 默认长期保存，用户可设置期限或随时删除。
- 删除原图和所有派生缩略图，保留不可恢复的墓碑。

### MVP-DATA-003 纠错与清除｜P0

- 单条服药事实通过撤销/修订纠正，不直接抹除。
- 支持清除研究事件和全部本机数据；全部清除同时销毁密钥。

### MVP-DATA-004 脱敏研究包｜P0

- 本机计算指标，用户主动授权并预览后导出。
- 默认排除照片、处方原图、药名、疾病、自由文本和稳定设备标识。
- 导出操作本身写入本地审计记录。

### MVP-DATA-005 加密备份｜P1

- 生成版本化、带认证加密的离线备份包并支持原子恢复。
- 忘记密码无法由平台找回。
- 公开测试前必须完成跨版本、篡改和中断恢复演练。

### MVP-PRI-001 应用锁｜P0

- 首次设置主动引导启用设备生物识别/PIN，但用户可跳过。
- 应用锁失败不得删除数据；提供回到系统凭据的安全恢复路径。

### MVP-PRI-002 截屏控制｜P0

- 敏感页面默认禁止截屏/录屏。
- 用户可通过全局开关放开；开启前展示风险提示并记录本地偏好。

# 6. 状态和数据规则

## 6.1 状态契约

```text
DoseLifecycle =
  scheduled | due | prepared | taken_confirmed | late_taken | missed | revoked

ItemConsumptionAssertion =
  pending | taken_as_planned | partially_taken | not_taken

PhotoEvidenceState =
  captured | skipped_with_reason | deleted_tombstone

AppearanceAssessment =
  suspected_change | unable | no_anomaly_signal
```

这些维度正交保存：照片状态和模型结果不能自动生成服用确认；任务生命周期不能覆盖逐药事实。

## 6.2 数量规则

| 字段 | 来源 | 用途 |
| --- | --- | --- |
| `detected_object_count` | 端侧模型 | 辅助用户观察画面；不得驱动库存 |
| `planned_dose_quantity` | 处方/方案 | 显示本次计划；可为小数 |
| `confirmed_consumption_quantity` | 用户逐药确认 | 唯一库存扣减依据 |

## 6.3 时间规则

- 计划时间至 `on_time_until` 确认为按时。
- `on_time_until` 后至 `record_until` 确认为晚服。
- 到达 `record_until` 仍未确认生成漏服事件。
- 漏服后的补录追加修订，不删除漏服事件。
- 时区或系统时间变化后暂停自动派生，先提示用户核对并重建未来任务。

## 6.4 修订规则

- 处方、外观、确认和库存均采用版本或追加流水。
- 撤销必须引用被撤销事实；修订必须引用前一版本。
- 任何库存反向调整与修订在同一事务中提交。

# 7. 端侧视觉门禁

## 7.1 模型目标

- 画质判断。
- 药片样物体检测与总数计数。
- 个人当前基准范围内的异常分数。
- 可靠拒绝判断。

## 7.2 禁止用途

- 不做开放式药名识别、成分判断或真伪鉴别。
- 不将物体数换算为处方剂量。
- 不让模型结果自动确认服用或扣减库存。
- 不对特殊形态和同一种药的新旧外观混用强行输出外观结论；首版不输出尺寸变化原因。

## 7.3 评测指标

- 计数准确率和计数绝对误差。
- 明显错误组合的漏报率。
- 正常组合的误报率。
- 无法判断率和人工回退率。
- 不同机型、光线、背景、遮挡和反光下的分层结果。
- 半片、破损、透明胶囊和同一种药的新旧外观混用必须验证为可靠回退；整组多种药同框必须作为合法场景单独验证。

算法门槛未达到时，可关闭外观变化功能，但不得阻塞照片、人工确认和库存主链。

# 8. 隐私与离线要求

- P0 核心不得发起网络请求，不集成远程遥测或远程崩溃上报。
- 模型和安全文案随安装包发布，不在运行时下载。
- 锁屏默认不泄露药名、剂量、疾病和 HIV 等敏感信息。
- 原图默认加密长期保存；保留策略变化只影响未来自动清理，主动删除立即执行。
- 研究包导出和未来备份是用户主动操作，不得后台自动上传。
- 未指定正式首发地区前，不内置地区专属医疗处置规则。

# 9. 非功能要求

| 类别 | 要求 |
| --- | --- |
| 性能 | Android 目标机型冷启动到首页可交互 P95≤2 秒；照片加密落盘≤1 秒 |
| 稳定性 | 相机、模型或通知异常不得破坏人工闭环；关键写入具备事务和恢复 |
| 电量 | 不常驻相机、不持续后台推理；分析仅在用户拍照后触发 |
| 兼容 | Android 先行；最低版本和支持机型由 Phase 0 真机验证冻结 |
| 可访问性 | 当前不设专项功能，但不得阻止系统字体缩放和基础读屏；完整无障碍列入 Future |

# 10. 研究指标

## 10.1 本机事件

- 提醒计划、通知打开、相机打开、拍照保存、跳过拍照。
- 已准备、逐药确认、部分服用、晚服、漏服和撤销。
- 疑似变化、无法判断、模型错误和人工回退。
- 库存修订、照片删除、研究包生成和清除。

事件不保存照片内容、药名、疾病、自由文本或可跨安装追踪的标识。

## 10.2 成功判断

- 参与者能在无研究人员现场帮助下完成首次建档和一次日常任务。
- 整组拍摄与跳过兜底使核心任务完成率达到研究方案预设目标。
- 多药和部分服用时，逐药事实与库存流水一致。
- 模型失败不会显著降低人工确认完成率。
- 参与者理解照片和端侧分析不代表吞服或用药安全。

# 11. 验收用例

1. **整组拍摄：** 一张照片关联三个药项，保存后为已准备；逐药确认后分别扣减。
2. **逐药拍摄：** 三张照片分别关联药项，任务仍使用同一生命周期。
3. **部分服用：** 两种药按计划、一种药部分服用，库存按三个实际量变化。
4. **跳过照片：** 保存原因后可确认，时间线明确显示无照片。
5. **半片：** 计划量为 0.5 片，模型物体数与剂量分开，外观返回无法判断。
6. **同药混合外观：** 同一种药的新旧批次并行时关闭外观判断，只保留照片和人工确认；不同计划药物共同入镜仍按整组模式处理。
7. **模型失败：** 照片已保存、分析失败，用户仍可逐药确认。
8. **晚服/漏服：** 两个阈值分别产生按时、晚服和漏服；补录保留原事件。
9. **撤销：** 撤销一次已服记录后生成等量反向库存流水。
10. **通知异常：** 权限关闭、精确闹钟不可用、重启和时区变化均能被发现并重建。
11. **隐私：** 锁屏隐藏药名；敏感页默认阻止截屏；全局开关可显式放开。
12. **删除：** 删除照片后无原图/缩略图残留，但存在墓碑；全部清除销毁密钥。
13. **研究导出：** 未授权不能导出；授权后包内不含照片、药名、疾病和自由文本。
14. **断网：** 飞行模式下完整执行提醒后的全部核心流程。

# 13. 风险与降级

| 风险 | 降级 |
| --- | --- |
| 每次拍照负担过高 | 默认整组一张、手动快门、跳过原因、人工确认 |
| 模型误报或漏报 | 只报疑似变化/无法判断，人工最终确认，可整体关闭外观功能 |
| 相机或模型不可用 | 无照片人工确认；主链继续 |
| 系统通知未送达 | 权限/调度自检、前台重建、测试提醒；不承诺绝对送达 |
| 记录错误导致库存错误 | 撤销、修订和反向库存流水 |
| 本机照片泄露 | 私有加密、应用锁引导、锁屏隐藏、截屏默认阻止 |
| 无备份导致数据丢失 | 内部研究明确告知；公开测试前完成 P1 备份恢复 |
| 研究数据过度收集 | 本机计算、最小字段、导出预览、主动授权和可退出 |

## MVP 结论

本 MVP 验证的是“照片记忆凭证＋逐药人工确认＋离线记录闭环”，不是自动识药或医疗决策。端侧模型可完全关闭，提醒、拍照/跳过、已准备、逐药确认、库存、异常、复诊和研究导出仍必须独立成立。
