> 产品需求文档（PRD）｜内部研究原型产品基线

| 项目 | 内容 |
| --- | --- |
| 核心人群 | 需要长期规律服用口服片剂或胶囊的成年患者 |
| 重点场景 | 高血压、糖尿病口服药、慢性乙型肝炎、HIV 感染等长期用药 |
| 当前实现基线 | 《长期用药管理APP_MVP_离线版_v0.1》；如本文与 MVP 冲突，以 MVP 为准 |

> **安全声明**  
> 本产品只帮助用户记录医生已经确定的长期用药方案。照片表示用户曾准备并记录画面中的药物，不表示药物已被吞服。端侧视觉能力只做实物计数和外观变化提示，不能确认药物成分、剂量或服用安全。发生疑似重复服用、严重不适、自伤风险或其他紧急情况时，用户不应等待 App 判断，应联系专业人员或当地紧急医疗服务。

# 1. 产品定位与原则

## 1.1 产品机会

长期用药行为高度重复，用户可能无法仅凭记忆判断自己是否已经服药、服了哪些药。普通“已服用”按钮缺少情景线索，纸质处方、库存、漏服原因和复诊事项又往往分散。本产品用带时间的照片和明确的人工确认，把这些信息连成可回看的本地记录。

## 1.2 核心原则

1. **照片是记忆凭证，不是吞服证据。**
2. **记录先于模型。** 模型失败不得阻断照片保存和人工确认。
3. **人工确认是唯一服药依据。** 只有逐药确认才改变库存。
4. **异常提示而非正确性保证。** 端侧模型只提示疑似变化或无法判断。
5. **实物计数与处方剂量分离。** 看到几个物体不等于服用了多少剂量。
6. **离线核心独立成立。** 提醒、拍照、确认、库存、复诊和异常记录不依赖网络。
7. **不把依从性工具变成医疗决策工具。** 不提供补服、加倍、停药或改量建议。
8. **隐私默认保护。** 锁屏隐藏敏感内容，照片留在应用私有空间。
9. **纠错留痕。** 错误记录通过撤销和修订纠正，不覆盖历史事实。
10. **研究参与可退出。** 数据只有在用户主动授权导出后才离开设备。

## 1.3 关键术语

| 术语 | 定义 |
| --- | --- |
| 服药任务 | 某计划时间对应的一组药物，可包含多个药项 |
| 任务药项 | 一次任务中的单种药物及计划剂量 |
| 已准备 | 已保存照片，或用户说明跳过拍照原因；不表示已吞服 |
| 患者确认 | 用户逐药说明实际服用情况和数量 |
| 当前外观基准 | 单种药当前唯一启用的包装、厂家/批次和药片参考照片 |
| 异常提示 | 对数量或外观变化的辅助提醒，不是药物或剂量判断 |
| 照片墓碑 | 原图删除后保留的最小记录，用于说明曾存在照片及删除时间 |

# 2. 阶段范围

## 2.1 当前离线 MVP

当前范围由离线 MVP 文档完整定义，包括：

- 手工录入处方、用药方案、库存、复诊和检查事项，并保存原始照片。
- 每日固定时间或每周指定日期的本地提醒。
- 通知直达相机，手动拍摄；默认整组一张，也可配置逐药拍摄。
- 无法拍照时记录原因并继续人工确认。
- 端侧实物计数、疑似外观变化提示和拒绝判断。
- 已准备与已服用分开；同一任务逐药确认、逐药扣减库存。
- 漏服、晚服、缺药、疑似重复服用、副作用和医嘱暂停记录。
- 本地照片时间线、库存预测、复诊摘要和脱敏研究包导出。
- 本地加密、可选应用锁、截屏控制、照片保留和数据清除。

## 2.2 当前明确不包含

- 账号、服务器、云同步、远程配置、在线问诊或第三方 API。
- 大模型咨询、服务器识图、自动处方识别或 OCR。
- 药物相互作用、食物禁忌或个体化服药指导。
- 照护者远程提醒、远程查看或远程修改。
- 虚拟宠物、植物成长或其他奖励机制。
- 自动快门、语音输入、药名播报和专项无障碍模式。
- 按需用药、单双日/周期性交替剂量和复杂疗程规则。
- 开放式识药、药品真伪判断、剂量正确性判断和吞服证明。

## 2.3 长期愿景候选

以下内容保留为未来路线，不得被当前团队当成 MVP 需求：

- 经合规评估后的账号、加密同步、授权照护和跨设备恢复。
- 大模型辅助整理复诊问题、副作用描述和处方变化；模型不得自主给出医疗处置。
- 经药师审核、可追溯来源和版本的药物知识提示。
- 经验证的 OCR、自动快门和更广剂型支持。
- 非惩罚性的虚拟植物或宠物互动。
- 系统化无障碍、语音和多语言支持。
- 与合规医疗机构的摘要分享或真人咨询入口。

# 3. 用户与主要旅程

## 3.1 目标用户

- 年满 18 周岁，已经获得明确处方或医嘱。
- 使用口服片剂或胶囊，并能本人完成最终确认。
- 可接受照片仅作为个人记忆记录，而非医学凭证。
- 内部研究参与者已经完成知情同意，可随时退出。

未成年人、无法独立确认服药的人、需要即时临床处置的人及需按需用药或复杂交替剂量的人不进入当前研究原型。

## 3.2 首次设置

1. 阅读产品边界、照片用途和研究说明。
2. 选择是否启用设备生物识别/PIN 作为应用锁。
3. 手工录入处方和药项，拍摄处方、包装和药片正反面。
4. 为每种药启用一个当前外观基准；特殊形态标为“只人工确认”。
5. 录入总药量、单位、提醒时间、正常窗口结束和最晚记录时间。
6. 选择整组拍摄或逐药拍摄；默认整组一张。
7. 手工录入复诊、取药和检查事项。
8. 完成通知权限和提醒自检。

## 3.3 日常服药

1. 本地通知默认只显示中性提醒，不显示药名和剂量。
2. 用户点击通知直达相机，也可进入“无法拍照”。
3. 用户手动快门；照片先加密保存，再运行端侧分析。
4. 保存照片或说明跳过原因后，任务进入“已准备”。
5. 页面展示照片、检测到的实物总数及必要的异常提示；不展示肯定性安全结论。
6. 用户逐药选择按计划服用、部分服用或未服用，并填写实际数量。
7. 完成确认后生成库存流水和时间线记录。

## 3.4 异常与纠错

- 端侧分析失败、超时或设备不支持：保留照片，转人工确认。
- 半片、破损片、透明胶囊或新旧外观并行：不做外观判断。
- 用户不确定是否已经服药：展示照片时间线和历史确认，不替用户下结论。
- 疑似重复服用或出现不适：结构化记录，展示经审核的通用安全分流。
- 记录有误：创建撤销和修订，自动生成相反库存流水。
- 已判漏服后补录：保留原漏服事件，追加实际时间和修订关系。

# 4. 功能需求

## 4.1 处方、药品和计划

### FR-RX-001 手工录入

- 用户按既有处方手工录入药名、剂型、规格、单次计划量、单位和备注。
- 当前阶段不使用 OCR，也不根据照片自动生成处方。
- 处方原图只用于回看，不能覆盖结构化字段。

### FR-RX-002 版本与暂停

- 处方变化创建新版本，旧版本不可覆盖。
- 复诊日提醒用户核对并录入新处方。
- 医嘱暂停期间不生成新的服药任务，但保留恢复和复诊事项。

### FR-MED-001 外观基准

- 每种药只能有一个当前启用外观基准。
- 基准至少关联包装、厂家/批次备注及药片正反面照片。
- 新厂家、新批次或明显外观变化需要建立新基准。
- 新旧外观并行使用期间关闭该药的外观判断。

### FR-REM-001 计划类型

- 支持每日固定一次/多次和每周指定日期计划。
- 疗程结束日期可选；未填写表示持续有效。
- 不支持按需用药和复杂交替剂量。

### FR-REM-002 时间窗口

- 每个方案必须设置提醒时间、正常窗口结束和最晚记录时间。
- 正常窗口后确认记为晚服；最晚记录时间后仍未确认记为漏服。
- 后续补录不得删除原自动生成的漏服事实。

### FR-REM-003 通知可靠性

- 本地系统通知是尽力而为能力，不承诺绝对准时送达。
- 权限关闭、系统限制或调度异常时，App 必须显著提示并提供修复指引。
- 每次前台启动、自启恢复和方案变化后重建未来提醒。

## 4.2 拍照与视觉记录

### FR-CAM-001 拍摄模式

- 默认整组药拍一张；用户可按方案改为每种药分别拍摄。
- 一张整组照片可关联同一任务中的多个药项。
- 当前阶段使用手动快门；自动快门只保留为未来路线。

### FR-CAM-002 跳过拍照

- 用户可选择相机故障、环境不便或其他原因跳过拍照。
- 跳过后记录为“无照片人工确认”，不得伪造照片状态。
- 跳过拍照不阻断逐药人工确认。

### FR-CAM-003 保存与删除

- 原图先写入应用私有加密存储，再开始分析。
- 默认长期保存；用户可配置保留期限或主动永久删除原图。
- 删除原图后保留照片墓碑，不保留可恢复缩略图。

### FR-VIS-001 端侧任务

- 检测照片画质和药片样实物数量。
- 在单一当前基准可用时检测明显的颜色、形状、纹理或刻印变化；首版没有实体尺度参照，不输出尺寸变化原因。
- 整组模式允许只给出整组异常提示，不强行定位到某个药项。

### FR-VIS-002 输出边界

- 用户可见结果只有“疑似发生变化”和“无法判断”。
- 内部状态 `no_anomaly_signal` 仅表示本次未触发异常阈值，不展示为通过、正确或安全。
- 模型不得输出药名、成分、真伪、服用剂量或是否可以服用。

### FR-VIS-003 特殊形态

- 半片、破损片、透明胶囊、严重遮挡/重叠，或同一种药的新旧厂家/批次/外观同时使用时返回 `unable`；合法的整组多种药同框不属于该条件。
- 特殊形态仍允许建档、拍照、人工确认和库存记录。

## 4.3 人工确认、库存和历史

### FR-LOG-001 两步语义

- 拍照成功或说明跳过原因后为“已准备”。
- 用户逐药确认后才形成服用事实。
- 已准备不得触发库存扣减或奖励。

### FR-LOG-002 逐药确认

- 每个药项独立选择：待确认、按计划服用、部分服用、未服用。
- 按计划或部分服用必须记录实际数量。
- 任务总状态由药项状态派生，不得用一次整组点击覆盖所有药项事实。

### FR-INV-001 库存流水

- 库存只按 `confirmed_consumption_quantity` 扣减。
- 仅拍照、已准备、漏服和未服用不扣减。
- 修订或撤销通过追加反向流水纠正，不直接改写历史余额来源。
- 半片可按 0.5 片等处方单位扣减，但模型的实物计数保持整数并与剂量字段分离。

### FR-LOG-003 历史回看

- 时间线展示计划时间、拍摄时间、确认时间、照片、逐药实际数量和异常记录。
- 用户可从时间线判断自己记录过哪些药，但 App 不推断吞服事实。
- 撤销、补录和照片删除状态必须可见。

## 4.4 库存、复诊和异常

### FR-INV-002 库存预测

- 根据当前余额和未来固定计划估算用尽日期。
- 开封瓶装、散装、丢失和人工修订场景标为预计库存。
- 缺药不会把过去任务改成已服用；药到后从新的任务继续记录。

### FR-FU-001 人工事项

- 复诊日期、取药日期和检查项目由用户按已有医嘱录入。
- App 只负责提醒、完成记录和摘要，不自动推荐项目或周期。
- 复诊日提示检查处方是否变化并建立新版本。

### FR-EXC-001 异常记录

- 支持漏服、晚服、疑似重复、缺药、医嘱暂停、副作用和不确定是否已服。
- 可记录时间、关联药项、症状、原因和自由文本。
- 只展示经医学审核的通用求助或紧急分流文案，不提供具体处置剂量。

## 4.5 隐私与研究

### FR-PRI-001 本地保护

- 结构化数据和照片加密保存，照片不进入系统相册。
- 首次设置主动引导用户启用设备生物识别/PIN 应用锁，但不强制开启。
- 锁屏通知默认隐藏药名、剂量、疾病和服药结果。

### FR-PRI-002 截屏

- 处方、药物详情和照片等敏感页面默认阻止截屏和录屏。
- 用户可在隐私设置中通过全局开关放开，并需确认风险提示。
- 复诊或研究分享优先使用受控导出。

### FR-PRI-003 数据权利

- 支持永久删除单张照片、清除研究事件和清除全部本机数据。
- 单条服药事实通过撤销/修订纠错；照片内容可物理销毁并保留墓碑。
- 清除全部数据时销毁数据库、媒体、密钥和本地诊断信息。

### FR-RES-001 内部研究

- 不使用后台遥测、崩溃上报或远程分析 SDK。
- 指标在本机计算，默认不包含原始照片、处方文本、药名或自由文本。
- 参与者主动授权后才生成脱敏研究包，并可在导出前预览范围。
- 研究必须有伦理审查、知情同意、招募/排除标准、退出和数据销毁流程。

# 5. 状态与数据契约

## 5.1 正交状态

状态必须分成四个互不替代的维度：

```text
DoseLifecycle:
  scheduled | due | prepared | taken_confirmed | late_taken | missed | revoked

ItemConsumptionAssertion:
  pending | taken_as_planned | partially_taken | not_taken

PhotoEvidenceState:
  captured | skipped_with_reason | deleted_tombstone

AppearanceAssessment:
  suspected_change | unable | no_anomaly_signal
```

- `prepared` 不表示 `taken_confirmed`。
- `AppearanceAssessment` 不得修改 `DoseLifecycle`。
- `no_anomaly_signal` 是内部诊断值，不生成肯定性用户文案。
- 多药任务只有在所有药项完成确认后才算任务确认完成；部分药项可保持待确认。

## 5.2 核心数量字段

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| `detected_object_count` | 模型在画面中检测到的物体数 | 整数；可为空；不代表剂量 |
| `planned_dose_quantity` | 该药项的计划剂量 | 可为小数，如 0.5 片 |
| `confirmed_consumption_quantity` | 用户确认的实际服用量 | 由用户输入；库存唯一扣减依据 |

## 5.3 核心实体

- `PrescriptionVersion`：不可覆盖的处方版本及原图引用。
- `Medication`：药物显示信息和库存单位。
- `MedicationAppearanceVersion`：单个当前外观基准及历史版本。
- `Regimen`：固定日/周计划和两个时间阈值。
- `DoseOccurrence`：单次任务的生命周期。
- `DoseOccurrenceItem`：计划量、确认状态和实际量。
- `PhotoEvidence`：加密媒体、拍摄方式、状态和删除墓碑。
- `PhotoMedicationLink`：照片与任务药项的多对多关系。
- `AppearanceAssessment`：独立端侧分析结果及模型版本。
- `InventoryLedgerEntry`：追加式库存变化及修订关联。
- `ExceptionRecord`：漏服、副作用等结构化记录。
- `ResearchExport`：用户授权的脱敏导出记录。

# 6. 非功能与安全要求

## 6.1 离线与可靠性

- 安装包包含运行核心流程所需的模型和内容，不在运行时下载。
- 无网络、模型关闭或模型崩溃时，人工闭环必须完整可用。
- 首页冷启动到可交互 P95 目标不超过 2 秒；照片写入完成目标不超过 1 秒。
- 数据写入采用事务；应用被杀死后不得出现已扣库存但缺少确认事实的状态。

## 6.2 提醒边界

- 通知权限、系统强制停止、精确闹钟权限和厂商省电策略均可能影响送达。
- 产品必须展示当前提醒健康状态，提供测试提醒和系统设置入口。
- 不使用“保证准时”“绝不漏提醒”等承诺。

## 6.3 安全门禁

- 数据库、媒体和密钥保护完成威胁建模和真机验证。
- 数据库、照片、密钥不得进入系统自动备份。
- 正式公开测试前完成版本化加密备份、恢复和篡改/中断演练。
- 内部真实患者研究开始前至少完成本机数据清除、研究导出和退出流程。

# 7. 研究与验收

## 7.1 核心研究问题

1. 通知直达相机、默认整组一张的流程能否被长期接受？
2. 照片时间线能否降低“今天是否已经服药”的不确定感？
3. 异常提示型视觉能力能否在不过度误报的前提下发现明显变化？
4. 逐药确认是否能准确处理多药、部分服用和库存变化？

## 7.2 本地指标

- 提醒打开率、任务准备率、逐药确认率和拍照跳过率。
- 从通知打开到完成确认的耗时。
- 疑似变化率、无法判断率、人工回退率、用户纠正率。
- 晚服、漏服、撤销、部分服用和库存修订次数。
- 研究包导出及撤回状态。

## 7.3 必测场景

- 整组一张、逐药拍摄、多药中只服一部分。
- 无法拍照、模型失败、模型超时、低质量照片。
- 半片、破损片、透明胶囊，以及同一种药的新旧外观混用。
- 正常、晚服、漏服和漏服后补录。
- 记录撤销、库存反向流水和照片永久删除。
- 通知权限关闭、设备重启、时区变化和系统时间修改。
- 应用锁、截屏开关、全部清除和主动研究导出。

# 8. 长期路线

## 8.1 联网与大模型

未来如引入大模型，只允许在用户主动发起且明确联网的场景中：整理记录、生成复诊问题草稿、把副作用描述转为结构化摘要。模型不得自行生成处方、判断是否补服、建议加倍/停药或把照片解释为已吞服。

## 8.2 照护与奖励

授权照护、远程提醒、虚拟宠物/植物和生成式互动均需单独的隐私、授权、撤销和非惩罚设计，不进入当前离线 MVP。

## 8.3 正式发布

内部研究原型不等同于商店发布或医疗器械结论。确定首发地区、产品宣称和数据流后，必须重新评估适用的隐私、医疗软件、消费者保护和研究要求。

## 文档结论

当前产品首先是一个离线的长期用药记忆与记录工具。照片提供回忆线索，端侧模型只辅助发现可能的变化，逐药人工确认才形成服药记录。所有联网、大模型、照护和奖励能力都属于未来路线，不得进入离线 MVP 的范围、依赖或验收。
