# Release 构建失败原因与修复方案（2026-08-27）

## 1. 结论

上一轮包含三个相互独立的问题，不能合并成一个“构建失败”结论：

1. 覆盖旧测试数据后首次启动曾在 `expo-sqlite` 的 `exsqlite3_finalize` 发生原生崩溃；代码防护、自动化测试和修复后 Release 的可复现场景复验现已完成，结果见第 7 节。
2. 数据库修复后的 Release 重建在配置阶段失败，因为 Gradle 缓存生成了不含实现类的 Expo Dev Launcher 插件 JAR；这不是业务代码、依赖声明或插件源码缺失。
3. 随后的恢复任务因子智能体额度耗尽而中断；它不构成新的代码、构建或运行结论。

当前代码已通过 29 个测试文件、138 项测试。SHA-256 为 `AAD669ECD417A371933E9ABC49BFF3395E5ABCF5C19F8C0C7D1A5B5BFE803C59` 的旧 x86_64 Release 生成于 SQLite 修复之前，已归档且不得作为当前候选包；当前候选包的哈希见第 7 节。

## 2. 运行时故障定位

| 项目 | 已确认事实 |
| --- | --- |
| 触发条件 | 保留旧应用沙箱，覆盖安装修复前 Release，Metro 未监听，飞行模式首次冷启动 |
| 实际结果 | 约 4 秒后 SIGSEGV，堆栈指向 `libexpo-sqlite.so exsqlite3_finalize` |
| 对照结果 | 清空沙箱后相同包可以断网冷启动并稳定运行 |
| 根因范围 | 旧明文/不兼容 SQLCipher 数据库认证错误路径，以及 Expo SQLite 关闭时的语句重复 finalize 风险 |

已完成的最小防护：

- 认证后的 `sqlite_master` 探测改为 `execAsync`，不再为该错误路径创建 NativeStatement；
- 数据库打开参数固定为 `useNewConnection: true` 和 `finalizeUnusedStatementsBeforeClosing: false`；
- 认证或迁移失败只关闭连接并报告错误，不删除主库、WAL、SHM 或 SecureStore 密钥；
- 专项测试 10/10、全量测试 138/138、类型、Lint 和平台配置检查通过。

上述修复最初只能证明代码和自动化契约；2026-08-28 已补充修复后 APK 的 Android 原生复验，范围和限制见第 7 节。

## 3. Release 构建阻塞定位

修复后 `assembleRelease` 在项目配置阶段约 1 分 37 秒失败，错误为无法加载 `expo.modules.devlauncher.DevLauncherPlugin`。失败构建将 Kotlin 编译错误判定为 `UP-TO-DATE`，随后使用了约 655 字节、仅含插件描述文件的转换 JAR。

核查结果：

- `expo-dev-client 57.0.14`、插件源码和插件描述文件均存在；
- 正常插件 JAR 为 12,325 字节并包含 `expo/modules/devlauncher/DevLauncherPlugin.class`；
- 问题来自 included-build 的项目缓存、增量任务状态和 Gradle transform 缓存不一致；
- 只删除 transform 只能临时恢复，复用旧项目缓存会再次产生不完整产物。

## 4. 确定性构建方案

项目使用 `npm run build:android:release:verified` 作为唯一的本轮 Release 构建入口。脚本必须：

- 加载 `D:\help_u_surivive\android-dev-shell.ps1` 的项目局部 Java/SDK/Gradle 环境；
- 停止项目 Gradle daemon，并把停止后的 daemon 状态写入本次证据目录；
- 将旧 APK复制到 `.toolchains/build-evidence`，防止新构建覆盖历史证据；
- 首次恢复时将 Expo Dev Launcher 插件旧 `build` 输出隔离并保全证据；确定性脚本随后复制归档已核验完整的输入，不再反复移动正确产物，也不修改插件源码；
- 最初尝试使用唯一的新项目缓存，但 Gradle 因任务快照路径变化而重编全部 included-build，并触发 Windows Kotlin 增量文件锁；最终流程先把最后一次成功使用的 `.gradle-release-retry` 完整复制到证据目录，再在原路径复用其任务历史，并执行读写探针；
- 固定 x86_64、单 worker、禁用并行和 build cache；构建前验证并归档 Dev Launcher 的完整插件 JAR，不对所有 included-build 使用全局 `--rerun-tasks`；
- 复用成功任务历史，使其他 React Native/Expo included-build 保持 `UP-TO-DATE`，避免 Windows 锁定 Kotlin 增量文件时触发全量重编删除；
- 禁用 Gradle 实验性 HTML problems report，完整控制台日志仍写入证据目录，避免 Windows 占用旧报告文件导致非业务失败；
- 验证插件 JAR 包含 `DevLauncherPlugin.class`；
- 验证 APK 确实由本次构建生成，且哈希不同于修复前旧包；
- 保存完整构建日志、APK 大小、时间和 SHA-256。

脚本不得清除 SDK、全局依赖缓存、模拟器沙箱、数据库、密钥或用户源码。插件仍缺少实现类时立即停止并保存证据，不进行无界重试。

## 5. 新 Release 验收

新包先完成静态门禁：内嵌 JavaScript bundle、无 `application-debuggable`、无 `INTERNET`/`SYSTEM_ALERT_WINDOW`/外部存储权限、`usesCleartextTraffic=false`、`allowBackup=false`、Expo Updates 关闭、签名校验通过并明确为内部 Debug 证书。

API 36 模拟器按以下顺序验证：

1. 清空测试沙箱后的无 Metro、飞行模式冷启动，稳定至少 30 秒；
2. 安装修复前 Release 并启动生成加密库，再覆盖安装新 Release，确认不崩溃且保留合成数据；
3. 在可调试验证包中注入同名明文或损坏数据库，确认无 SIGSEGV、文件不变、密钥不销毁且没有自动清除；
4. 第二次冷启动和前后台切换，确认连接关闭幂等；
5. 测试结束恢复模拟器网络。

无法取得真实 v3 加密数据库时，`v3 → v4` 原生覆盖升级继续标记为未验证，不得由 Node 测试替代。

## 6. 准入规则

| 构建、静态、干净安装和旧数据覆盖通过，真机未完成 | 附条件通过，仅限合成数据内部测试 |
| 真机安全/通知和人类专业签署未完成 | 始终保持 `realPatientDataAllowed=false` |

本轮不新增业务功能，不自动迁移、删除或修复无法认证的数据库，也不以清空沙箱作为升级解决方案。当前 x86_64 包不是 ARM 真机包或公开发布包。

## 7. 实际执行结果（2026-08-28 收口）

### 7.1 构建

- 新增 `scripts/build-android-release.ps1` 与 `npm run build:android:release:verified`；脚本归档旧 APK、插件输入、项目缓存和完整日志，并拒绝旧哈希。
- Windows 沙箱不允许在 `android` 和 `node_modules` 的部分生成目录写入；获得项目构建权限后，Gradle 越过文件锁。唯一新缓存会导致所有 included-build 重编并触发 Kotlin 增量文件锁，因此最终先归档、再复用最后一次成功项目缓存的原路径。
- Expo Dev Launcher 插件真实执行 `compileKotlin`/`jar`，生成 JAR 含 `DevLauncherPlugin.class`，原 655 字节转换包问题未复现。
- `assembleRelease`：`BUILD SUCCESSFUL in 11m 45s`，873 个任务（61 executed、812 up-to-date）。

- 内嵌 `assets/index.android.bundle`，ABI 只有 x86_64；无 debuggable 标志。
- 无 `INTERNET`、`SYSTEM_ALERT_WINDOW`、读写外部存储权限；`usesCleartextTraffic=false`、`allowBackup=false`、Expo Updates=false。

- 测试结束已恢复飞行模式关闭、Wi-Fi 开启和非 root ADB。

### 7.3 最终边界

结论为**附条件通过，仅限虚构数据内部测试**。没有可用的真实 schema v3 历史 APK，因此 v3→v4 原生覆盖升级仍未验证；ARM/实体 Android 手机、正式签名、安全取证、通知长测和人类专业签署仍是公开测试与真实数据准入门禁，`realPatientDataAllowed=false`。
