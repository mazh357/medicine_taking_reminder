# 长期用药管理 APP｜需求—测试追踪矩阵

> 本文把离线 MVP 的 35 个唯一需求 ID 映射到交互、数据/ADR、测试套件和可审计证据。若本文与离线 MVP 冲突，以离线 MVP 为准。本文不扩大产品范围，也不把自动化测试当作 Android 真机证据或专业签署。

## 0. 使用规则

### 0.1 覆盖标记

| 标记 | 含义 | 最小通过条件 |
| --- | --- | --- |
| N | 正常路径 | 合法输入产生预期事实、页面状态和审计结果 |
| A | 异常路径 | 非法输入、失败或中断被拒绝/回滚，不产生错误事实 |
| D | 降级路径 | 平台或模型能力不可用时进入指定人工路径，主链不被静默阻断 |
| P1 | 后续门禁 | 当前不得实现或展示为已有能力；在 Gate D 前补齐证据 |

- 每个 P0 需求至少包含 N、A、D 中一种；涉及平台或可选能力的需求必须包含 D。
- 测试套件 ID 与需求一一对应：`TS-<需求 ID 去掉 MVP->`。套件内的场景后缀为 `-N`、`-A`、`-D`。因此每个测试都有明确来源需求，不允许建立无 MVP ID 的孤立业务测试。
- 多需求端到端和故障注入场景使用 `SC-*`；每个 `SC-*` 必须在本文第 3 章显式列出来源需求。
- “通过”只表示软件行为符合冻结契约，不表示药物、剂量、吞服或医疗安全正确。

### 0.2 证据层级

| 层级 | 证据 |
| --- | --- |
| L1 | 单元/属性测试结果、Zod 与纯 TypeScript 领域断言 |
| L2 | repository、SQLCipher、迁移和事务契约测试；数据库前后快照 |
| L3 | React Native 组件/应用 E2E；页面录像与可访问文本断言 |
| L4 | Android 真机、故障注入、安全/性能证据包；不得由模拟器替代 |
| L5 | 医学、药学、隐私、伦理或研究负责人签署；不得由软件测试替代 |

## 2. 测试套件契约

### 2.1 一一对应规则

- `TS-ACC-001` 至 `TS-PRI-002` 共 35 个套件，分别以同名 MVP ID 为唯一主来源。
- 套件可引用另一个需求作为前置，但不得把该前置的验收责任据为己有。
- 每个自动化结果必须包含：套件 ID、场景后缀、代码版本、schema/模型/文案版本、设备或运行环境、开始/结束时间和通过/失败原因。
- 每个 L4 结果必须引用 Phase 0 证据目录；仅写“真机测过”不算证据。

## 4. 门禁与缺陷规则

| 门禁 | 必须通过 | 允许降级 | 直接阻断 |
| --- | --- | --- | --- |
| Gate B 正式业务编码 | 35 项有追踪；P0 契约和状态测试规格可执行；Phase 0 S00–S08 有结果 | 精确提醒近似化；视觉整体关闭 | SQLCipher/媒体加密/事务/密钥/备份排除/截屏安全失败 |
| Gate C 真实患者研究 | 全部 P0 套件、14 项 MVP 验收和目标设备 L4 证据；L5 专业签署 | 视觉关闭、相机跳过、近似提醒，但必须在同意与界面中可见 | 未审医疗文案、数据明文/丢失、人工主链中断、研究导出越权 |
| Gate D 公开测试 | Gate C + `TS-DATA-005` 完整恢复演练 | 无 | 备份无法认证、不可原子恢复、跨版本不兼容或首发地区未冻结 |

缺陷严重性：

- S0：可能给出医疗处置/肯定性正确结论，或错误自动确认/扣库存；立即停止测试和分发。
- S1：明文泄露、密钥/删除失败、事务不一致、错误任务深链、无授权导出；阻断当前 Gate。
- S2：可恢复的提醒、相机、模型、性能或交互问题；必须有明确降级和用户提示。
- S3：不改变事实或隐私边界的布局/非关键文案问题；进入缺陷列表但不可掩盖可访问性问题。

## 5. 自动检查

交付时执行以下静态检查：
