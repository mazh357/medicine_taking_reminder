# 个人本地测试版功能验收记录（2026-08-27）

## 1. 验收结论

本轮库存预测、补药提醒、复诊/取药/检查事项、历史筛选、数据清除和通知可靠性已经进入代码与自动化测试。2026-08-28 收口复跑 `npm run check`，平台配置、TypeScript、ESLint 和 29 个测试文件中的 138 项测试全部通过。修复后 Android x86_64 内部 Release 已生成并完成静态和 API 36 升级复验。

验收结论：**附条件通过，仅限虚构数据内部测试。** 修复后 Release 构建、权限/签名、干净离线冷启动、修复前包覆盖升级、异常明文库保护、第二次冷启动和前后台切换均通过；原 `exsqlite3_finalize` SIGSEGV 未复现，合成数据、数据库和密钥均得到保留。真实 v3 包、ARM 真机安全证据、正式签名和人类专业签署仍未完成，因此 `realPatientDataAllowed=false`，不得录入真实药名、处方、照片或其他个人健康数据。

本记录只证明当前列出的代码、自动化和文件产物事实，不证明通知绝对送达、物理吞服、药物或剂量正确，也不代表真实患者研究或公开发布准入。

## 6. 残余风险

- 原生通知已经调度、数据库投影保存前进程退出时，仍可能形成系统孤儿通知；需增加系统计划通知与本地投影主动盘点。
- 通知、媒体、数据库和密钥无法组成单一跨资源原子事务；当前依靠持久 pending 标记、失败门禁和幂等重试，仍需真机中断演练。
- 修复前 schema/运行时覆盖旧测试数据会触发原生 SQLite finalize 崩溃；修复后 Release 已完成同场景和明文异常库复验，但真实 v3 历史包仍缺失。
- Debug 文件哈希只证明产物身份，不证明安装后行为、安全属性或与真实手机兼容。
- Node 与静态测试不能证明锁屏隐私、物理文件删除、Keystore、备份和厂商通知调度行为。
