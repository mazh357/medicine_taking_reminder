# 长期用药管理 APP｜测试策略与 Android 设备兼容矩阵

> 本文定义如何验证离线人工主链、数据一致性、Android 系统能力和安全降级。它不证明药物、剂量、吞服或临床安全正确。真实患者研究前，自动化、模拟器和智能体结论均不能替代真机证据及医学、药学、隐私、伦理人类签署。

## 0. 质量目标与硬边界

### 0.1 质量目标

1. 模型、相机、通知或网络不可用时，用户仍可完成“查看任务→说明跳过原因→已准备→逐药确认→库存→回看”。
2. 任一进程中断、重复点击或事务失败都不得产生“有确认无流水”“有流水无确认”或重复扣减。
3. 照片、数据库和密钥不得以明文进入日志、相册、系统备份或未授权研究包。
4. 任务状态、逐药状态、照片状态和视觉状态正交；三个数量字段不得互相赋值。
5. 系统提醒只作尽力而为提示；失败必须可发现、可解释、可重建，不以送达与否推断服药事实。
6. 每个失败都落入稳定错误码、明确用户恢复路径和可复现证据，不静默清库或联网兜底。

### 0.2 零容忍失败

- 面向用户出现“药物正确”“剂量正确”“识别一致”“可以服用”或等价肯定性结论。
- 模型、照片、通知或任务级状态自动生成逐药确认或库存扣减。
- 数据库/WAL/SHM、照片、缩略图、密钥或默认研究包出现禁止明文。
- 错误/缺失密钥时创建新明文库、覆盖旧密钥或静默清除。
- 确认、撤销、修订或库存事务部分提交。
- 未授权生成研究包，或后台网络请求/运行时下载模型、代码、阈值或文案。
- 敏感页面默认可被系统截图/录屏或最近任务预览显示内容。

### 0.3 冻结测试契约

测试夹具、断言、导出解析器和页面文案必须使用以下完整枚举，不得自创同义状态或把任一维度合并：

```text
DoseLifecycle =
  scheduled | due | prepared | taken_confirmed | late_taken | missed | revoked

ItemConsumptionAssertion =
  pending | taken_as_planned | partially_taken | not_taken

PhotoEvidenceState =
  captured | skipped_with_reason | deleted_tombstone

AppearanceAssessment =
  suspected_change | unable | no_anomaly_signal
```

数量断言固定分离 `detected_object_count`、`planned_dose_quantity` 和 `confirmed_consumption_quantity`：前者只能为非负整数或空，后两者是规范化十进制定点字符串；只有最后一项能驱动库存。

## 2. 自动化测试设计

### 2.1 领域单元与属性测试

#### 状态机

- 穷举 `DoseLifecycle` 的允许/拒绝转换；非法转换必须返回 `ILLEGAL_STATE_TRANSITION` 且不写事件。
- 穷举 `ItemConsumptionAssertion × planned × confirmed`：pending 只能为空；not_taken 固定 0；taken_as_planned 必须等于计划；partially_taken 必须为正且不同于计划。
- `PhotoEvidenceState` 只允许 `captured → deleted_tombstone`；跳过不能变伪照片；补拍必须创建新事实。
- `AppearanceAssessment` 的三种状态不改变生命周期、逐药事实和库存；`no_anomaly_signal` 不进入用户结果卡。

#### 数量与库存

- 对 QuantityText 合法/非法边界、规范化、三位精度、最大值和千分之一 `bigint` 运算做表驱动与随机属性测试。
- 生成随机确认/撤销/修订序列，断言余额等于全部流水之和；每个有效正数量确认恰有一条等量负向消耗；每个撤销恰有一条等量正向反转。
- 重放同一幂等键应返回相同引用且不增加事实/流水；相同键不同 payload 必须为 `IDEMPOTENCY_CONFLICT`。

#### 时间与计划

- 覆盖正常截止前 1 ms、等于截止、截止后 1 ms、最晚时间前/等于/后，以及下一任务边界。
- 每日多次和每周指定日期使用冻结时区生成任务；历史任务时间快照不随方案改变。
- 时区/系统时间变化和 DST 不存在/重复时间不静默重算，返回 `TIME_ZONE_REVIEW_REQUIRED`。

### 2.2 组件与文案测试

- 所有药项卡分别提交；页面没有“一键全部按计划服用”及其他批量赋值控件。
- `prepared` 总与“尚未确认已服用”同时可被视觉和读屏读取。
- 物体数旁必须显示“这不是服用量”；不能位于实际量输入或库存列。
- 视觉用户卡只允许“疑似发生变化”“无法判断”；对 `no_anomaly_signal` 断言不存在结果卡。
- 锁屏预览夹具不含药名、剂量、疾病、异常和结果；安全分流占位未签署时不可进入真实患者构建配置。
- 系统字体放大和基础读屏不阻止主要按钮、逐药数量输入和错误恢复；当前不把专项无障碍扩展为新范围。

### 2.3 数据库、迁移和契约测试

- 空库 `user_version=0 → 1`、v1 重开、未知高版本拒绝、错误 checksum、迁移中断、重复执行和损坏输入。
- 个人本地测试版必须另测：旧未加密测试库受控清理、加密 schema v2→v3→v4、v3→v4 原地保留、覆盖安装首次/二次启动、前后台切换及错误/缺失密钥不自动清库。2026-08-28 修复后 x86_64 Release 已通过修复前包覆盖、异常明文库、二次启动和前后台切换；真实 v3 历史包仍缺失。
- 每次测试后运行 `foreign_key_check`、唯一索引、不变量查询和投影重建比对。
- group 照片可关联多个同任务药项；per-item 恰一项；跨任务关联返回 `PHOTO_LINK_SCOPE_MISMATCH`。
- 确认、修订、撤销、漏服、补录和删除状态机按数据契约第 9 章黄金序列做数据库前后快照。
- 照片删除 pending 阶段不可解密展示；只有文件/缩略图验证不存在后才提交墓碑。
- `research_event` 和导出序列按字段白名单反序列化；未知必需枚举拒绝，未知可选字段按版本规则处理。

### 2.4 应用 E2E

必须自动化或半自动化执行[追踪矩阵第 3 章](需求测试追踪矩阵_v0.1.md)的 `SC-CORE-01`、`SC-CORE-02`、`SC-TIME-01`、`SC-VIS-01`、`SC-TXN-01`、`SC-MEDIA-01`、`SC-SEC-01` 和 `SC-EXPORT-01`。`SC-REM-01` 可自动验证应用侧自检与重建，但实际通知送达和 OEM 行为必须真机人工取证。

E2E 数据固定使用虚构药物代号 A/B/C、合成几何图片、固定 UTC/IANA 时区夹具和无医学含义的占位文案。测试包不得包含真实处方、患者姓名、疾病或药片照片。

### 2.5 可测试性端口

正式实现可提供仅在测试签名包启用的本地端口：时钟、UUID、模型输出、存储失败点、事务失败点、通知系统投影和密钥读取结果。要求：

- release/research 构建中经静态扫描证明端口不可达且无调试菜单。
- 故障开关只接受本地预置枚举，不监听网络、不执行任意脚本。
- 所有测试事件使用合成 ID；日志不记录密钥、自由文本或完整文件路径。

## 3. 故障注入矩阵

| 故障 | 注入时机 | 预期状态/恢复 | 禁止结果 | 主要追踪 |

## 4. Android 真机矩阵

### 4.1 强制设备槽位

设备代号与 Phase 0 保持一致。Android 16/API 36 是本文更新日的当前稳定平台回归基线；执行时若出现更新的稳定 Android，新增该版本为 D-C，不删除 API 36 回归。

| 代号 | 系统/API | 性能档位 | 强制设备特征 | 主要目的 |
| --- | --- | --- | --- | --- |
| D-L | Android 8/9，API 26–28 | 低：arm64、3 GB RAM、低端 CPU、剩余空间≤2 GB 补测 | 无需 Google 服务；需真实后摄 | 最低 API、冷启动、SQLCipher、媒体落盘、CPU 推理降级线 |
| D-M | Android 11，API 30 | 中：4–6 GB RAM | 至少一台具有积极省电/自启动管理的中国市场 OEM 设备 | Android 12 前备份规则、重启/省电/进程限制、常见相机 |
| D-N | Android 14，API 34 | 高：6 GB+ RAM | 至少一台非参考 OEM；通知权限和精确闹钟默认/撤销路径可操作 | 现代权限、截屏、Keystore、生物识别、性能上界 |
| D-C | Android 16，API 36（截至 2026-08-23） | 当前：8 GB+ RAM、64 位 | Pixel/近原生参考设备；记录当日最新安全更新 | 当前平台行为、target SDK 回归、与 OEM 结果对照 |

每个槽位必须记录厂商、型号、SoC、ABI、RAM、Android/安全补丁/构建号、API、屏幕尺寸、剩余存储、电池优化、自启动设置、生物识别类型、Google 服务有无、APK/模型 SHA-256。模拟器只能补充确定性自动化和故障注入，不能占用槽位。

替换规则：目标型号不可获得时，只能用同一 API 区间、同等或更低 RAM/CPU（性能下限测试）、相同 OEM 系统家族的真机替换，并在 Gate 报告说明；不得用高端参考机替代 D-L 或积极省电 OEM 槽位。

### 4.3 支持级别判定

| 级别 | 判定规则 | 用户可见行为 |
| --- | --- | --- |
| 支持 | 最低 API 满足；SQLCipher、媒体加密、事务、人工主链和隐私硬门槛全部通过；P0 性能预算达标 | 完整人工功能；视觉按门槛开启；提醒显示实际健康状态 |
| 降级支持 | 安全/数据硬门槛通过，但视觉性能/兼容、精确提醒、相机可用性或生物识别之一受限；指定回退已验证 | 关闭视觉、近似提醒、无照片人工确认、设备凭据或关闭可选应用锁；明确显示原因 |
| 不支持 | 低于冻结最低 API/ABI；SQLCipher 或 AES-GCM/Keystore 不可用；事务/密钥/备份排除/敏感显示任一安全硬门槛失败；人工主链无法可靠保存 | 阻止内部研究安装或启动健康数据建档；不得用明文或联网替代 |

单台设备的视觉失败不得把安全可靠的人工主链判为不支持；应判为“降级支持：视觉关闭”。精确闹钟不可用同理，但必须能显示近似提醒及持续健康告警。最低 API 只有 S00 证据和 ADR-001 修订签署后才能调整。

## 5. 无法被自动化替代的真机证据

以下项目即使已有单元/E2E 也必须人工取证：

1. 通知权限允许/拒绝/撤销、精确闹钟设置、Doze、OEM 省电、重启、强制停止和实际触发误差。
2. 相机权限、实际快门、方向、后台切换、低光/模糊提示、缓存明文生命周期和低存储。
3. SQLCipher/WAL/SHM 原始文件扫描，错误密钥、进程强杀和升级后读取。
4. Keystore/SecureStore 在设备凭据、生物识别变化、卸载重装和全部清除后的行为。
5. 系统截图、录屏、投屏和最近任务预览；使用第二台设备外拍敏感页面保护结果。
6. Android 11 及以下与 Android 12+ 的备份/恢复规则和 D2D 行为。
7. TFLite CPU 推理耗时、峰值内存、温升/连续运行、模型关闭和低端设备系统杀进程。
8. 最终 release-like APK 的飞行模式、网络抓包、内嵌 bundle/模型和 `updates.enabled=false`。

所有真机证据沿用 Phase 0 的 `environment.json`、`procedure.md`、`metrics.csv`、外拍/截图、脱敏日志、SHA-256 清单和 `result.json`。证据不得包含真实患者数据。

## 6. 性能、稳定与长测

### 6.1 性能门槛

每台设备预热 5 次、正式 30 次，报告 P50/P95/max；使用单调时钟。

| 指标 | 门槛 | 失败处理 |
| --- | --- | --- |
| 冷启动到首页可交互 | P95≤2 秒 | S2；优化后重测，研究前必须达标 |
| 通知点击到相机可操作 | P95≤2 秒 | S2；不得绕过加密加载或显示错误任务 |
| 1280px 长边照片加密落盘 | D-L P95≤1 秒 | 可固定降低采集分辨率并重测；仍失败阻断相机照片能力 |
| SQLCipher 打开 | D-L P95≤500 ms；500–1000 ms 仅 Spike 降级 | >1000 ms 或不稳定阻断 Gate B |
| TFLite CPU 单次分析 | P95≤3 秒 | 超时/内存压力即该设备视觉关闭 |
| 通知长测 | 每设备至少 30 个触发点 | 报误差分布/缺失，不用均值掩盖；精确失败可近似降级 |

### 6.2 稳定性长测

- 7 天合成计划长测：每日多次、每周指定日、计划暂停/恢复、重启和跨午夜；逐日核对意图、投影、通知和任务数。
- 500 次随机确认/撤销/修订属性序列：每步重放库存和投影；每 25 步模拟强杀重开。
- 200 张合成照片循环：拍摄、加密、分析/关闭、删除；监测孤儿文件、数据库引用、峰值空间和内存增长。
- 20 次全部清除：每次确认数据库、媒体、研究事件、日志和密钥不可再访问，重新初始化不会连接旧事实。

长测中任何 S0/S1 立即停止并保全证据；不得通过自动重试掩盖首次失败率。
