# 个人本地测试版高风险验收记录

> **历史证据提示：** 本文记录 2026-08-25/26 当时的代码、APK 和模拟器结果，不覆盖 2026-08-27 当前代码。当前结论以[2026-08-27 功能验收记录](个人本地测试版功能验收记录_2026-08-27.md)为准；本文列出的旧 Release APK 不得作为当前候选或安装依据。

## 1. 结论

本轮新增和既有自动化共 87 项全部通过，平台门禁、TypeScript 类型检查和 ESLint 均通过。Android x86_64 调试 APK 与内部 Release APK 均已完成原生构建和 API 36 模拟器安装；Release 包经系统确认为不可调试，并在模拟器断网且 Metro 未监听时完成冷启动，直接进入“今天”。SQLCipher 和本地 AES-GCM 模块已进入实际编译及 APK；但当前版本仍不得宣称完成个人真实数据准入，因为 SQLCipher 磁盘取证、AES-GCM 篡改、Keystore 异常、照片物理删除、备份恢复和锁屏显示尚无 Android 真机证据及人类签署。

验收结论：**不通过（可继续使用合成数据开发；不得录入真实药名、处方或照片）**。

## 5. 阻塞项与处置要求

### 已解决：平台门禁迁移

`scripts/verify-platform-config.mjs` 已迁移到个人本地模式，并强制要求 `personalLocalMode=true`、`encryptionRequired=true`、`realPatientDataAllowed=false`。通知默认渠道已统一为 `medication-reminders-v2`。

后续要求：只有真机安全证据和人类签署完成后，才可通过独立评审变更真实数据门禁；不得仅修改开关取得准入。

### P0：原生安全与隐私缺少真机证据

当前 Node 测试证明的是调用顺序、错误传播和不自动销毁，不证明磁盘密文、Android Keystore、Auto Backup 排除或锁屏实际表现。

处置要求：在 D-L/D-M/D-N/D-C 至少完成 SQLCipher/WAL/SHM、AES-GCM 篡改、照片删除、密钥异常、备份恢复和锁屏外拍取证，产出标准证据包。

### P1：双列选择器缺少组件级交互自动化

项目未配置 React Native 组件测试工具，本轮只能锁住结构与纯时间计算，无法自动验证取消、旋转、返回、滚动吸附和 TalkBack 动作。

处置要求：后续引入与 Expo 57/React 19 兼容的组件测试工具，或先按真机清单逐项取证；不得仅凭源码静态测试判定交互验收通过。

## 6. 建议的下一次验收顺序

1. 在真实 Android 设备安装已生成的内部 Release APK，完成 SQLCipher 磁盘取证、AES-GCM 篡改、密钥失败和备份排除验证。
2. 执行照片删除的成功、文件失败、墓碑失败、三处强杀及重试场景。
3. 执行同日多任务、23:30 跨日、计划修改、暂停/恢复、重启和提醒权限恢复长测。
4. 用第二台设备外拍各 OEM 锁屏通知，确认标题、正文、通知历史均无药名和剂量。
